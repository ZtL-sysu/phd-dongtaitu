# 博士研究计划：离线三模块实施方案

## 文档状态与阅读方式

本方案依据《Event Driven Spiking Dynamic Graph Networks for Nonstationary Temporal Graph Forecasting》20页研究计划制定，聚焦 RQ1、RQ2、RQ3 的离线工程实现，不开展在线服务、真实部署或在线参数学习。

- **[RP]**：研究计划明确规定的机制、协议或候选设置，附节号和页码。
- **[首版决策]**：为了可以直接开发，本方案为RP尚未规定的细节选定的起点，不是RP原文、已证明最优的设计或实验结果。
- **[后续]**：暂不进入第一轮开发的内容。

这是开发规格，不是已完成模型或实验报告。配套 `reference_semantics.py` 仅是已经执行检查的关键状态语义参考；它没有实现完整预测模型，也没有跑真实数据性能实验。目录和命令在明确标注处属于待开发接口。

## 1. 第一版到底交付什么

第一版交付一个能执行以下过程的研究程序：

历史窗口数据 → 因果输入及质量摘要 → 稀疏动态图 → 关系调节的快慢脉冲记忆 → 多步预测。

固定训练好的模型后，再执行：

历史窗口内的新观测 → 轻量调度判断 → 选择性刷新图行和/或状态 → 每步预测读出。

在线运行暂不做，但**调度器仍然要在离线测试中真正执行**，否则无法检验第三个模块。

### 1.1 范围

[RP：§4.2–4.4、§5.2] 实现稀疏预测关系、关系条件化记忆、独立图/状态调度；主协议是相同长度历史窗口。

[首版决策] 优先完成：

1. 64节点可控模拟，验证语义和已知关系切换；随后256节点做规模检查。
2. email-Eu-core-temporal 的每日节点活动预测，完成第一个真实数据闭环。
3. MOOC活动量作为第二个适配任务，在前两项通过后再接入。

[后续] 原生贸易分布预测、推荐/交易排名、持续跨预测起点的状态运行、学习型调度器、理论证明、系统部署。它们仍是RP后续内容，不以“暂缓”代替最终研究承诺。

### 1.2 不在第一版添加什么

不做可视化网站、API服务、消息队列、强化学习调度、PSO大规模搜索、多个图学习器的复杂集成、十几个SNN内部微步。第一版先固定一个可解释实现。

研发顺序：

**数据与简单基线 → 连续状态动态图 → 快慢脉冲状态 → 关系调节记忆 → 冻结权重的调度 → 真实执行计时。**

“程序跑通”“机制有效”“获得实际加速”是三个独立验收结果。

## 2. 任务、时间与数据契约

### 2.1 预测任务

[RP：§4.1、表2、§5.2] 固定训练定义的节点集合。email使用过去28个日区间，报告1、3、7天预测；MOOC使用过去24个小时，报告1、6、24小时预测。

[首版决策] 读出层直接输出连续的1到Hmax个未来区间，email的Hmax=7，MOOC的Hmax=24。评价时分别取指定偏移，并保存其余预测。这里`t+3`表示第3个未来区间的活动量，不是未来3天的累计量。RP没有完全展开这个语义，本版明确固定，后续不混用。

### 2.2 数组

| 名称 | 形状 | 含义 |
|---|---|---|
| `values` | `[T,N,F]` | 可观测输入；不是评估目标的替代副本 |
| `input_mask` | `[T,N,F]` | 1为可用观测，0为不可用 |
| `obs_age` | `[T,N,F]` | 距最近有效观测的区间数 |
| `targets` | `[T,N,F]` | 保存用于训练/评价的目标值 |
| `target_mask` | `[T,N,F]` | 目标是否可用于监督/评分 |
| `interval_end` | `[T]` | 预测起点按已关闭区间的末端解释 |
| `node_ids` | `[N]` | 训练信息定义的节点映射 |
| `events` | 按时间索引的记录表 | 只为构造已发生交互先验使用 |

一个批次是 `[B,L,N,F]`。第一版调试和计时用B=1；训练可在相互独立的窗口间批处理。窗口内的时间顺序不能打乱。排序时保留同时间戳的确定次序。

两个mask必须分开。鲁棒性实验可以遮挡输入，但保留原本已知的目标用于评价；调度器只读被提供的输入，不能从干净评估目标取数。

### 2.3 三种“年龄”不要混淆

- `obs_age`：多久没得到有效观测。
- `graph_age`：多久没执行昂贵的图行刷新。
- `state_age`：多久没执行昂贵的神经状态更新。

每步进行便宜的时间衰减，不意味着 `state_age` 归零。收到新数据，也不意味着图或状态已经刷新。

### 2.4 真实数据预处理

[RP：§5.1–5.2、§5.6] email的节点是成员，输入特征为每日收件量和发件量，F=2。MOOC核心预测节点是课程活动，F=1，为每小时活动次数；不是对所有用户节点预测辍学。

[官方源核对] SNAP email原始记录为`SRC DST UNIXTS`，时间是从0开始的相对秒数。MOOC为`ACTIONID USERID TARGETID TIMESTAMP`；附带的辍学标签涉及之后是否停止活动，第一版完全不载入该标签文件。

执行要求：

1. 记录源页面、下载时间、原始文件SHA256、数据格式及文件大小。
2. 区间使用半开形式`[bΔ,(b+1)Δ)`。区间关闭后才能使用其中记录。
3. 无已知完整截止时刻时，首版保守排除最后一个可能不完整区间，并在manifest记录规则。
4. email没有唯一事件ID，不能把所有重复`(u,v,t)`自动删除；相同三元组可能代表真实重复消息。保留并报告数量。MOOC重复导入的同一ACTIONID需核验并记录处理。
5. 不用没有真实日历语义的相对时间生成星期几、节假日等特征。
6. 数据集按已发布记录视为观察到的活动，不宣称其覆盖现实世界全部行为。零事件与不可用记录严格区分。
7. 核心节点只由训练部分选定；后续新节点暂不纳入核心评分，记录排除数量及后续适配事项。

### 2.5 切分与标准化

[RP：§5.2] 真实活动数据按时间70%/10%/20%划分，保存准确边界。一个训练或评估样本的全部目标区间必须落在所属分区内。验证和测试允许读取起点之前的历史，但不能读取未来。

[首版决策] 计数输入使用`log1p`后按训练统计量标准化；预测头输出原始计数尺度的非负值。输入缺失位置经过掩码后填0，同时保留mask和年龄，不把0解释成真实活动量。原始量纲MAE/RMSE始终从原始目标计算。

归一化统计仅拟合训练部分并冻结。动态交互先验、滚动摘要和候选搜索必须在预测起点可用；不能在早期起点使用未来交互。

活动相似度候选是RP允许的另一条候选来源，但首版先用历史接触+有界探索，避免先写复杂检索器。后续相似度实验使用预先声明的训练校准前缀或因果滚动摘要，不能以全数据相关矩阵冒充逐时可用先验。

## 3. 可控模拟：先知道模型有没有做对

[RP：§5.1] 64节点起步、256节点扩展；稀疏动态系统；谱半径目标0.8；关系身份变化与边权变化分开；10%/30%依赖变化；缺失率0/10/30/50%；去除burn-in；测试使用新轨迹。

[首版决策] 首轮只跑64节点、无缺失、一次突变。通过后才开鲁棒性组合，不能一开始跑笛卡尔积。

### 3.1 具体生成式

`x[t] = W[t] @ x[t-1] + epsilon[t]`

构造非负、对角为0、行和为1的稀疏矩阵`P[t]`，每行最多8个非自身邻居。取：

`W[t] = 0.2 * I + 0.6 * P[t]`

这样每行和为0.8，统一无穷范数小于1。任意切换或端点凸插值仍保持这个界；这比只检查各端点谱半径更强，避免稳定端点切换后仍出现数值发散。这个构造是首版选定的生成器，不是RP给出的唯一公式。

- 默认保存有效2048步，之前丢弃256步burn-in。
- 每条轨迹用自身种子在有效长度的30%–70%之间抽取切换位置；渐变扩展初始持续128步。精确位置只进入评估元数据，不进入模型/调度器。
- 创新项先用零均值有界均匀噪声；默认幅度0.05。
- 关系身份变化：重新连接部分非对角支持后重新归一化。
- 权重变化：固定支持，修改相对权重。
- 渐变：在保持上述范数界的端点间插值。
- 非结构冲击：只改变噪声或加入短暂输入冲击，不改变P。
- 非线性扩展：`x[t] = W[t] @ tanh(x[t-1]) + epsilon[t]`。

首版模拟是连续实值预测，输出允许负值；不能对其强行套计数softplus头。

### 3.2 划分与隔离

模拟采用独立轨迹训练/验证/测试，例如训练轨迹种子0–7，验证100–101，测试200–203。每条轨迹内部仍按时间前向处理。它不同于真实单条时间轴的70/10/20协议，报告时分开说明。

真实生成矩阵、关系切换时刻、干净被遮挡输入，分别放入`oracle_metadata`或评估文件。模型和调度器不能访问。首版正常候选只能由可见历史和固定随机探索生成，不能直接使用真实P作为输入；若另做oracle候选诊断，必须单独命名。

### 3.3 第一轮必须看的结果

预测误差、图行变化强度、关系变化后的误差恢复、图/状态刷新比例、图/状态年龄。结构恢复仅作受限模拟诊断，不能因为预测正确就声称识别出真实因果边。

## 4. 公共运行时与接口

[首版决策] 独立维护预测模型参数和运行时缓存。权重属于`model`；动态图、神经状态、年龄、上次预测属于`runtime`。保存/重置两者的规则分开。

建议接口：

```python
class ForecastModel:
    def init_runtime(self, batch_size, n_nodes, device): ...
    def monitor(self, observation, runtime): ...
    def plan_actions(self, monitor, runtime, policy): ...
    def refresh_graph(self, observation, runtime, row_ids): ...
    def advance_clock(self, runtime, delta_t): ...
    def update_states(self, observation, runtime, node_ids): ...
    def readout(self, runtime): ...
    def step(self, observation, runtime, policy): ...
```

缓存建议包含：

```text
neighbors          [B,N,k]        # 不含自环，padding有显式有效位
weights            [B,N,k]
neighbor_valid     [B,N,k]
candidates         [B,N,K]        # K<=4k
u                  [B,N,2,2,c]    # 时间尺度×本地/邻居×通道
spike_pending      [B,N,2,2,c]    # 延迟复位待消费事件
pending_log_g      [B,N]          # 尚未应用的邻居记忆保留量
last_input         [B,N,F]
last_input_valid   [B,N,F]
previous_pred_1    [B,N,F]
previous_pred_valid[B,N,F]
graph_age          [B,N]
state_age          [B,N]
obs_age            [B,N,F]
cheap_summary      [B,N,Dsmall]
```

mask、时间、原始事件截止信息是显式字段，不能从数据填充值猜测。按批次、节点和时间步保留可追溯索引。

## 5. 模块一：置信度感知的稀疏动态图

### 5.1 输入与输出

[RP：§4.2] 使用近期节点摘要、历史交互频率、mask、观测年龄等给候选边打分。每个节点最多k个入邻居，自身另保留通路，候选上限K<=4k。

[首版决策] 初始`k=8,K=32`，节点过少时实际值截断至`N-1`。约定`A[i,j]`表示节点i预测时参考节点j，消息方向为`j→i`。

候选优先来自允许历史内的已接触节点；不足的部分由固定种子的有界探索补足。候选更新、探索和评分分别记操作数。首版每8个区间允许一次有界探索；每次探索最多对每个获准刷新行检查K个候选，禁止隐式N×N检索。

### 5.2 轻量摘要与置信度

[首版决策] 维护有效值比例q、截断标准化残差r、最近变化和观测年龄：

`r_i(t) = clip(mean_valid(|x_i(t)-pred_i(t|t-1)| / scale_i), 0, r_max)`

- `scale_i`由训练观测的稳健尺度估计；MAD为0时回退到通道级稳健尺度，并用正数下界保护。
- 计数数据的尺度下界首版取1；标准化的模拟数据另设非零下界。
- 没有前一步预测时，`residual_valid=false`，残差不参与优先级，靠初始化刷新。
- 当前输入缺失时，不能用干净目标制造残差。
- 对残差用一个短期EWMA减小单点冲击影响。q和残差摘要在所有方法中使用一致的允许历史。
- 监测量与残差在训练图中停止梯度，避免优化器通过操纵调度统计获得虚假的收益。

### 5.3 边分数与支持

采用共享的小MLP：

`score_ij = MLP(summary_i, summary_j, prior_freq_ij, masks, ages)`

从K个有效候选中选择top-k，然后只在选中支持上归一化。没有有效邻居时邻居消息置0，继续走本地通路，不能对全负无穷向量做softmax。

PyTorch实现可对选中的分数反向传播；支持索引本身是离散选择。要记录选中权重的梯度，并用有界探索避免候选永久锁死。相同分数使用候选ID的确定性排序消除支持抖动。不要把一个依赖不稳定并列选择的测试当成确定性保证。

### 5.4 图训练目标

[RP：§4.2] 预测损失、稀疏约束和置信度调节的时间一致性。

[首版决策] 第一版用显式top-k保证稀疏，`lambda_sparse=0`；时间项为：

`L_graph = L_forecast + lambda_temporal * mean_i(w_i * |A_i(t)-A_i(t-1)|_1)`

初始`lambda_temporal=0.01`，只作为试跑值；`w_i = w_min + (1-w_min)/(1+q_i*r_i)`，初始`w_min=0.1`。

这使可靠的大残差时减少平滑约束；观测不足时仍倾向保守。公式是首版决策，不保证能自动区分一切噪声。raw mask/age仍直接输入评分网络，使质量信息可影响前向关系生成；不是在测试时继续计算损失和更新权重。

行归一化后，`sum(abs(A))`往往只是常数，不能把它当有效稀疏正则。

V9关闭置信度时保留相同原始输入、候选和探索日程，固定置信度分支、令时间平滑权重为常数；具体开关写入配置，不能顺便扩大候选空间。

### 5.5 关系变化信号

[RP：§4.3] 刷新获得新行后，在新旧支持并集上计算：

`c_i = 0.5 * ||a_i_new - a_i_old||_1`

两行都是有效归一化分布时c∈[0,1]。初始化或完全无邻居的边界另定义并测试：首版首次构图不触发遗忘，c=0；有/无邻居互换时将其作为明确变化事件，约定c=1，并在日志中标记，而不是套不满足归一化条件的界。

不允许按排序后的第1、第2个位置直接相减：旧第1邻居和新第1邻居可能不是同一节点。必须按节点ID对齐。

图没有获准刷新时，不计算新图和c。真正的c只能用于刷新之后的记忆保留，不能成为刷新之前的免费调度信号。

## 6. 模块二：关系条件化的快慢脉冲记忆

### 6.1 固定总状态宽度

[RP：§4.3、表1] 两个时间尺度；本地与邻居通道分开；比较总宽度，而非模块个数。

[首版决策] 第一版`d_total=64`：

```text
fast-local:16    fast-neighbor:16
slow-local:16    slow-neighbor:16
```

总膜电位通道64，另外有对应脉冲/延迟复位缓存。d=32时四组各8。不能每组都设64再声称总宽度64。

局部输入只来自节点自身；邻居输入来自稀疏聚合。预混合层不得先把本地与邻居全部混合，再假装知道哪些记忆来自邻居。

### 6.2 编码与聚合

[RP：§4.3] 保留绝对水平与变化；不只编码差分。

[首版决策] 输入为标准化水平、相对最近有效观测的变化、mask和观测年龄。没有连续有效观测时，变化项置0并保留有效位，不能用填0制造尖峰。

```text
node encoding e_i = shared_encoder(level, change, mask, obs_age)
local current      = bounded_project_local(e_i)
neighbor current   = bounded_project_neighbor(sum_j A_ij * e_j)
```

`e_j`只需为获准更新节点及其所需源邻居的并集计算，不提前对全图做昂贵投影。如果并集接近N，实际节省也可能很少，必须记录这个并集大小。

第一版是混合连续编码、脉冲状态和连续读出，不宣称整条计算链完全脉冲化。

### 6.3 神经元与时间

[RP：§4.3] 泄漏积分发放，延迟复位；快慢tau正值；实际观察时间不同于内部模拟步。

首版每个数据区间一个内部步。tau初始化(1,8)，单位就是该数据集的区间。使用正值参数化，并保证tau_slow>tau_fast。tau(2,16)为后续候选。

原候选式为：

`alpha = exp(-delta_t/tau)`

`u_t = alpha*u_(t-1) + I_t - v*s_(t-1)`

`s_t = 1[u_t >= v]`

[首版决策] v固定为1；电流经`tanh`限制在[-v,v]；反向使用替代梯度，初始采用fast-sigmoid形式，斜率参数5。快慢通道的输入投影独立，单次外部观测不额外展开多个内部微步。

### 6.4 图变化只处理邻居相关旧记忆

[RP：§4.3] `g_i = exp(-beta*c_i)`，beta初始使用共享正值。

[首版决策] beta初值1、softplus保证正值。每次获准构图后执行：

`pending_log_g_i += -beta*c_i`

当节点真正执行昂贵状态更新时：

1. 对旧状态完成该时刻应有的衰减和上一步延迟复位。
2. 仅将邻居相关旧状态乘`exp(pending_log_g_i)`。
3. 加入当前本地/邻居输入电流。
4. 产生本时刻脉冲，并保存为下一个时刻的待消费复位事件。
5. 将`pending_log_g_i`清零。

本地通道不乘g。图先刷新但状态暂时未更新时，g继续累计；`readout`不私自提前使用它。这样与RP“先存储，待下一次昂贵更新时使用”的约定一致。

### 6.5 最容易出错的延迟复位

不能把“上次发过的脉冲”在连续跳过的每一步重复减去。首版每个数据步都执行便宜的`advance_clock`：

```text
base = alpha*u_old - v*spike_pending
spike_pending = 0
```

不触发昂贵更新：`u_new=base`，不加入新电流。

触发昂贵更新：对base的邻居部分应用待消费g，加入新电流，产生新脉冲。

在阈值固定、alpha≤1、g≤1、电流幅度≤v、从零初始化等首版约束下，可以保持`u<2v`。这保证一次待消费复位和零输入衰减后不会藏着未处理的再次发放。若后续放宽这些约束，必须重新检验零输入下的阈值事件，不能继续声称简单解析衰减总是有效。

首版宁可保留全节点的O(Nd)便宜衰减，也不要一开始实现跨多个时间步的懒更新。计时必须包含该成本。

### 6.6 读出与连续状态对照

[首版决策] 使用可学习的快慢混合权重，对两组膜电位的有界表示加权后拼接，再用共享线性/小MLP输出Hmax×F。读出在每个历史步执行，以提供下一步可用残差；窗口最后一个起点用于正式多步评分。计数头softplus，模拟实值头线性。

先训练连续状态对照，再切到SNN。连续对照保留相同图学习器、本地/邻居划分、快慢tau和总通道，使用不发脉冲的泄漏连续状态转移。参数总数及差异单独打印；不能拿宽得多的GRU作为“严格容量匹配”的证据。

外部GRU可以作为另外的简单预测基线，但不同于内部匹配控制。

## 7. 模块三：冻结权重后的确定性调度

### 7.1 两个开关

[RP：§4.4] 图行刷新G与状态刷新S独立。

| G | S | 行为 |
|---|---|---|
| 0 | 0 | 图复用；状态仅便宜衰减/复位；仍读出 |
| 0 | 1 | 用缓存图聚合当前可用特征，更新状态 |
| 1 | 0 | 更新图和关系变化量；累计g，不吸收当前状态电流 |
| 1 | 1 | 更新图；把累计关系变化应用于旧邻居记忆；更新状态 |

首次初始化按共同规则强制必要刷新，其成本计入所有策略。任何分支都不得略过该时刻要求的预测。

### 7.2 第一版不训练调度网络

[RP：§4.4、§4.6] 从确定性阈值规则起步，先用验证集选择主模型，再固定权重校准调度阈值。

[首版决策] 两个基础优先分数：

`score_g = q*r_smooth + graph_age/A_g + abs(q-q_prev)`

`score_s = q*r + state_age/A_s + abs(q-q_prev)`

初始权重全1。r_smooth来自过去残差的便宜EWMA，不是新邻接差异。对图使用更平滑证据，对状态允许更快响应，这是一个待验证的首版工程假设。

达到最大年龄、初始化、预定审计的动作是mandatory；超过阈值的动作是optional。图阈值与状态阈值分开选。

### 7.3 从动作配额到平均运行预算

第一步先实现图/状态名义更新比例0.25/0.5/0.75/1.0，验证逻辑。但把它叫“动作配额”，不叫已经满足的真实时间预算。

第二步在验证数据上标定：

- 基础成本：监测、年龄和衰减、读出、必要索引/先验维护。
- 图动作成本：实际刷新行数、候选数、探索量。
- 状态动作成本：活跃节点数和实际需要编码的源节点并集。

按mandatory优先，再按“启发式优先分数/估计增量成本”选择optional，直到名义预算耗尽。这里的分数不是预测收益的无偏估计，只是启发式。

成本受批量大小影响，不能只测一个节点的耗时再线性外推全部动作。先分组测几个活跃规模，再用查表或分段近似。最后一律以端到端实测结果为准。

[RP] 平均预算不等于每步硬约束。mandatory超预算时，执行并记录超额，不允许丢掉困难预测或假装不存在。

### 7.4 可行性检查

若每个节点两步内必须更新一次，则长期更新比例至少约50%。不能同时宣称“最高年龄2”和“始终25%更新”。图和状态各自检查。

首版默认最大年龄均为4、目标动作比例均为50%，审计采用确定性轮换，审计成本列入mandatory。低预算配置不自动降低安全标准；无法同时满足就报告不可行或超额。

### 7.5 必须真的跳过计算

不接受：`all_updates = expensive_model(all_nodes); output = gate*all_updates + (1-gate)*cache`作为节省计算的实现。

接受：先生成G、S的节点索引，再只调用相应图行评分/状态投影和聚合；合并重复源节点，批量执行活跃部分；最后scatter回缓存。所有共享预计算的成本仍记入总成本。

PyTorch原生索引和gather/scatter足够先写原型；不强制安装图扩展或稀疏编译工具。高层框架与自定义内核等到profile确实显示瓶颈后再考虑。

## 8. 单步执行顺序：开发者必须遵守

以下是待实现的接口顺序，不是已经存在的完整预测器：

```python
def step(observation, runtime, model, policy):
    # observation只含当前已关闭区间以及以前的可用信息
    monitor = model.monitor(observation, runtime)
    # monitor只读当前可观测x、mask、之前发出的1步预测、各种年龄

    graph_ids, state_ids = policy.plan(monitor, runtime)
    # 此时还没有新图，不能使用真正的new_A-old_A作免费判断

    model.advance_clock(runtime, observation.delta_t)
    # 消费上一步延迟复位恰好一次；推进时间；不重置昂贵更新年龄

    if len(graph_ids) > 0:
        new_rows = model.refresh_graph(observation, runtime, graph_ids)
        change = support_aligned_change(runtime.old_rows, new_rows)
        runtime.pending_log_g[graph_ids] += -model.beta * change
        runtime.replace_graph_rows(graph_ids, new_rows)
        runtime.graph_age[graph_ids] = 0

    if len(state_ids) > 0:
        # 只为这些节点及其需要的源邻居计算投影
        model.update_states(observation, runtime, state_ids)
        # 此方法只在neighbor通道消费pending_log_g，然后清零
        runtime.state_age[state_ids] = 0

    forecast = model.readout(runtime)          # 每步均执行
    runtime.previous_pred_1 = forecast[:, 0].detach()
    runtime.previous_pred_valid = True
    return forecast, runtime, audit_record()
```

实际代码中年龄究竟在monitor前还是advance_clock中增加必须统一：首版在进入monitor前先计算`effective_age=stored_age+delta_t`，动作结束后将未更新节点保存为effective_age，已更新节点设0。不能因调用顺序产生少一拍或多一拍。

图刷新后状态更新应使用新图；状态更新本身不把新邻居记忆再提前乘一次g。

## 9. 离线训练、验证、测试

### 9.1 主协议：独立历史窗口

[RP：§5.2] 所有方法读取同样L步。首版每个预测起点重置runtime，只在其L步历史中逐步维护状态。不同窗口之间不共享状态。

这样在线部署未实现，三个机制仍全部可测试。代价是窗口重叠会重复处理历史，效率结论只适用于这个窗口协议，不能外推成连续运行的收益。

候选先验/事件历史不能偷带未声明的窗口外动态信息。首版使用窗口内已发生记录；如另用固定训练前缀先验，所有匹配方法都获得同一先验，并记录其额外信息范围。

### 9.2 主模型训练

[RP：表1、§4.6] AdamW，学习率0.001或0.0003，梯度范数上限1，最多100epochs，patience10，先全量更新。

[首版决策] 起步lr=0.001，weight_decay=1e-4，float32，单内部脉冲步。短窗口先在L步内完整反传；TBPTT接口保留，若更长历史再启用，并在分段边界detach所有状态、图缓存和需要保留的计算图。不能跨不连续样本继承状态。

首版主损失为窗口最后起点的多步masked MSE；计数目标是原始计数尺度，模拟目标为原始实数尺度。监测需要的历史中间预测也会执行，但默认不额外加入辅助监督。后续若加入辅助一步损失，应作为显式实验开关，对匹配对照一致使用。

不同checkpoint产生的历史状态不可互相复用。验证每次从相同许可历史重新初始化。

### 9.3 验证与调度校准

保存主模型在验证上的最佳checkpoint，选择规则事先固定：指定预测偏移的平均MAE，另保留每个偏移和特征的指标。

然后冻结参数，启用选择性执行，在验证集选择图/状态阈值、最大年龄和预算。每套策略都从相同初始状态独立运行，不能沿用上一策略污染过的缓存。

阈值候选可取全量验证回放中优先分数的若干分位数，但最终要实际运行每个选择性策略，因为跳过更新后残差分布会变。不能把全量轨迹上的阈值模拟当成真实选择性运行。

每个新模块最多12个预先列明的pilot配置，不做全组合。校准期间不读取测试指标。

### 9.4 最终测试

冻结预处理、节点集合、checkpoint、图/状态规则、阈值、预算和评价切片。测试按时间排序窗口，参数不更新。对参数计算运行前后哈希，运行时cache不纳入权重哈希。

调度器用当前观测和此前已发预测形成反馈，不允许读取当前起点的未来目标数组。程序上让scheduler接口无法接收targets。

第一次开发只做一个种子和小测试；正式核心比较选一个配置跑五个种子。测试结果不作为再挑配置的依据；探索性返工必须标记为新的开发轮次和新冻结协议。

| M1 | 静态ANN和动态ANN；k/K与质量摘要 | 能训练、图真实随输入变化，梯度正常、无密集全对全隐藏路径 |

| M3 | 冻结权重，图/状态两个确定性开关 | 四种G/S分支正确、全开等价、全关真跳过 |
| M4 | 预算/最大年龄/周期随机对照、完整profile | 能画真实误差-成本曲线，包括负结果 |
| M5 | email完整协议与一轮内部消融 | 不靠模拟oracle也能跑通真实数据；输出日志/图/报告 |
| M6 | MOOC适配、外部强基线、五种子 | 只改适配器/输出头，不能为每个数据集暗改核心算法 |

这些是工作包而非承诺的日历工期，训练时长由本机profile决定。

模块一若只追随噪声，先简化置信度和候选；模块二若宽度匹配后无收益，保留负结果；模块三若索引开销太大，先合并活跃节点或采用分组更新，而不是先宣称SNN更节能。
