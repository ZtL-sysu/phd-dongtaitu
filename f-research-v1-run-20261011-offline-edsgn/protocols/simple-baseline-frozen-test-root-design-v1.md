# Root design: frozen persistence and train-fit pooled linear test route

The two simple baselines are required clean final-test rows on N64-main,
original email, MOOC and the separately fitted episode. They are deterministic
seed0 references, not five independently trained models. Preserve the existing
P3 train/validation output and original engine source. No actual final test is
authorized by this design.

The new isolated NumPy evaluator must reproduce unchanged engine.simple_baselines
evaluation semantics: persistence repeats the final provided raw observation
for all Hmax offsets; the pooled linear predictor uses the same normalized
L-bin node histories plus intercept and the already training-fitted coefficient
matrix, then clips its raw predictions at zero only for count data. It must
never refit coefficients, preprocessing or node mappings on test or rerun the
original fit-and-evaluate convenience function for split=test. Clean target
masks, all offsets and all complete ordered legal origins are preserved.

Linear coefficients and their completed P3 training-fit manifest, source,
training-window count, coefficient shape/dtype/byte hash and source-bound
development acceptance must be fixed before test. Persistence has an explicit
no-parameters identity rather than a fabricated neural checkpoint. Both bind
training-derived preprocessing/statistics, node order and data/source bytes.
An immutable separate pretest authorization binds method, domain/descriptor,
original fit evidence, actual parameter/coefficient state, exact future output
and current scientific source hashes. No original training output is changed.

Require accepted P3/P3A passed/pass, P4 running and the official before-P4
validator before any test numerical arrays are decoded. Snapshot the full
canonical state, all passed-stage refs, exact source/data/freeze refs and
complete source directory membership; recheck after the validator and
immediately before load, and after output serialization. Hold the separate
model-resource and campaign leases, verify ownership on release, refuse active
or stale foreign leases/processes, preserve failures, and use the same72-hour
aggregate budget callback throughout full-origin prediction. No test target
enters model input and no oracle array is loaded.

Each method/domain job writes predictions.npz, raw required-horizon/feature
metrics_by_horizon.csv and evaluation_manifest.json with scope=full_protocol,
split=test, n_windows=complete legal count, no smoke/limit, unchanged original
fit/coefficient bytes and explicit method/provenance. Its UUID original phase
receipt, independent stable alias and dispatcher completion receipt must bind
all consumed source/input bytes and serialized output hashes. CPU is the
declared deterministic evaluation device; these rows make no GPU speed claim.

This route needs separate metadata admission and dispatcher/phase engineering
before any actual launch. The globally complete test queue must explicitly
include all eight simple_v1 jobs, and a separately reviewed global verifier
successor must retain the existing five driver contracts while adding the
exact simple_v1 full-origin report/phase contract. All primary/ordinary/oracle
consumers must use that successor before actual P3A; the accepted global-v1
five-contract engineering interface cannot close an all-required campaign.
Do not silently omit these jobs or rename a simple driver as a neural driver.

CPU fixtures use temporary opaque metadata or small known arrays only. Verify
exact original persistence/linear numerical parity, train coefficient
immutability, count clipping, causal history/future invariance, full origin
coverage, no coefficient fitting in evaluation, gates-before-array-load,
pre-validator input mutation refusal, output/hash closure and owned lease
release. Positive public temporary paths are necessary; refusal-only/mock-loop
tests cannot certify a valid experiment route. Actual fit admission, full test
execution, global closure and simple-baseline outcomes remain pending.
