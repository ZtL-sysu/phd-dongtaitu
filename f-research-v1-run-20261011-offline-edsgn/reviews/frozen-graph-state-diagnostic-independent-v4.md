The test path checks canonical P2/P3/P3A `passed/pass`, P4 `running`, and hash-bound P3A evidence. Test collections and oracle files are byte-fingerprinted without decoding for authorization; the frozen checkpoint, runtime model source, diagnostics source, normalization helper, resource helpers, detailed trace selection, and freeze are validated. The full prediction loop finishes and revalidates the freeze/collection before oracle matrices are loaded; those matrices are only used in the subsequent alignment analysis. Detailed trace captures are limited to frozen sampled origins/nodes; compact trace rows stream to gzip and are checked against a byte allowance. The final report counts its own UTF-8 bytes and refuses cap overflow. Its estimate is per run/collection with a preflight free-disk check; it is not a whole-campaign storage guarantee, even if a 16/64 GiB cap is authorized.

**Blocking source-schema mismatch:** engine checkpoints store `history`, `hmax`, node count, and feature count in `payload["task"]`; config does not have `history` or `hmax`. The full replay instead indexes `payload["config"]["hmax"]` and `payload["config"]["history"]` (around prediction-size and artifact estimation), so the operational path will raise `KeyError` on the actual engine checkpoint schema. It also reads `ds.n_nodes` and `ds.n_features`, while actual `PreparedData` exposes shape through `ds.values.shape` and has no such attributes. Current toy tests do not invoke this full replay with actual `PreparedData`/engine checkpoint schema, so 17 passes do not cover these lines.

**Gate time-of-check gap:** stage and evidence hashes are checked at replay start, but the driver does not retain/recheck canonical `pipeline-state.json` bytes or P3A evidence hashes after replay/oracle analysis. A mid-run gate/evidence change can therefore go undetected. In contrast, the H2 v2 driver rechecks captured pipeline bytes and stage statuses at completion. Add equivalent final revalidation before the report is accepted.

These issues should be repaired and covered with a real-schema CPU fixture before any freeze or real replay. The current 8 GiB default and passing cap tests do not establish that full collections fit; cap capacity must be checked for each authorized collection at launch. This review makes no P3A/P4 gate decision and supports no scientific mechanism claim.
