# Split-history robustness v2 implementation review

V2 is an isolated successor; v1 and its independent review remain intact. The only new implementation files are `edsgn/staging/split_history_robustness_v2.py` and `edsgn/tests/test_split_history_robustness_v2.py`; toy receipts are `logs/split-history-robustness-v2-tests.log` and `.json`.

## Repairs verified

- Placement still uses complete `data.origins(split)`, history length, and trajectory shape only (`split_history_robustness_v2.py:61-86`). No target values/masks or outcomes enter block selection. It validates contiguous origins and half-open history bounds; the selected block is sampled uniformly from legal starts in that union using seed 2027, trajectory index, and source seed (`:240-270`). `trajectory_index` now rejects bools, strings, floats and negatives instead of truncating (`:32-38,246`).
- V2 records union-time rate separately from replay-weighted window geometry. `_window_coverage` weights each timeline bin by the number of complete origin histories containing it and reports input positions/visible counts, before/after missing fractions, newly hidden visible fraction, weighted block fraction, unique-union missing fractions, and source/final input-mask hashes (`:88-135`). These metrics enter both runtime perturbation summary and freeze row metadata (`:301-326,209-236`). A toy with pre-existing input-mask gaps checks hand-counted before/after and incremental fractions.
- Initializing inherited noise/jitter at missing rate zero and then replacing only final mask/normalized input/age preserves noise arrays, events and offsets (`:282-299`). All mask-dependent summaries are now recomputed after final visibility is installed, including clean-zero, observed noisy-zero and count-noise visible-position counters (`:301-316`). A zero-count toy reproduced and fixed the former 144-versus-114 stale-counter discrepancy. `target()` remains inherited and exact target/target-mask equality is tested. Age is recomputed on the final trajectory mask; normalized visible values retain the inherited train mean/std; hidden normalized and raw window inputs remain zero.
- Freeze validation now requires `wrapper_path.resolve() == Path(__file__).resolve()` (`:341-356`) and records the transitive `edsgn.robustness.py` SHA along with the wrapper SHA (`:203-212`). The strict versioned JSON domain-manifest contract is `schema="edsgn.split-history-domain.v1"`, with dataset identity (event kind, partition, source name, T/N/F, node-ID SHA, split bounds, L/Hmax) and ordered trajectory rows (index/source seed/input-mask SHA/split/origins/history union/allowed domain bounds). Exact structural equality rejects unknown/missing/tampered fields; source trajectory identity and bounds are cross-checked to the supplied PreparedData (`:142-200`). Bundle manifests bind the complete deterministic trajectory list (`:174-184,375-414`).
- Tests cover target-blind placement, val alias, weighted coverage with baseline mask gaps, unchanged targets, normalization/age/prefix semantics, count noise/jitter initialization and summary, random/group delegation, exact executing-wrapper requirement, dependency source tampering, strict domain/schema/range and truncated collection rejection, and invalid trajectory indices. Local `dyg-cold` CPU run: **12 passed**, `py_compile` passed (`logs/split-history-robustness-v2-tests.*`). No real data/targets, prediction arrays, model, GPU, optimizer, or replay was used.

## Remaining integration limits

This is still a staging adapter, not integrated into the robustness evaluator or canonical freeze path. Before any replay, the root must include these exact extras in the immutable test freeze and invoke the v2 validation on the same declared split and trajectory collection. The domain schema is newly defined by this staging implementation; no real domain manifest has been created or independently accepted. The manifest binds metadata and node/input-mask identities, not the complete raw bundle bytes; the existing engine-level dataset/preprocessing fingerprint must remain required. No robustness outcome is established by these toy checks.
