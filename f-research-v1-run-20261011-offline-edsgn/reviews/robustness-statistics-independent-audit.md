# Independent robustness and statistics audit

Date: 2026-10-11. Read-only audit of `statistics.py`, `robustness.py`, `engine.py`, and `data.py` interfaces. Existing focused toy tests were run; no source or prior evidence was edited. No optimizer training, T26, or formal experiment was run.

## Findings

**Overall: core paired bootstrap and input perturbation behavior are sound in the inspected paths, with two corrections needed before interpreting secondary RMSE or claiming perturbation-source freezing.** This review is a code audit, not scientific experiment acceptance.

The primary bootstrap first forms each seed's paired left-minus-right window scores, averages the five seed values within each window, then uses a single sampled temporal index vector per replicate for that already seed-averaged series. The observed estimate is the grand mean of the five seed means. This is the requested five-seed mean with shared temporal resampling, rather than treating five copies as independent trajectories (`statistics.py:118-125`). `_validate_pairs` groups rows by trajectory and sorts by origin, and `circular_block_indices` samples each group separately, so draws do not cross trajectory IDs (`statistics.py:36-58,61-83`). The primary multi-horizon score is computed inside each same window from the requested one-based horizons before this resampling, keeping horizon 1/3/7 or 1/6/24 paired for the primary contrast (`statistics.py:200-217,254-268`). The loader rejects mismatched targets, masks, origins, or paired seed IDs across the ten archives (`statistics.py:230-253`).

**Finding 1 — secondary RMSE uses macro window RMSE rather than engine pooled RMSE.** `_window_scores` takes a per-window root-mean-square across valid node/features and then the caller averages these window scores (`statistics.py:209-217,275-290`). The engine's reported RMSE instead computes one root after pooling all valid squared errors (`engine.py:182-187`). These differ when the number of valid targets per window varies. Minimal observed example: window 1 has two valid zero errors; window 2 has one valid error of 10. Current macro window RMSE is `(0+10)/2 = 5`; engine pooled RMSE is `sqrt(100/3) = 5.7735`. This affects the secondary RMSE label/interpretation (and likewise macro-vs-pooled MAE with unequal valid counts), not the ordinary all-observed equal-mask case. Minimal fix: either label and document these secondary results as equal-window macro metrics, or bootstrap sufficient per-window squared-error sums and valid counts, compute pooled RMSE per resample for each side, then take the paired difference. Do not describe the current number as matching engine RMSE.

**Finding 2 — robustness recipe digest is bound, but perturbation implementation source is not included in the test freeze.** `engine.freeze_checkpoint` records only its `runtime_files` subset in `prediction_source_sha256`; that set includes `data.py`/`engine.py` and model files but omits `robustness.py` (`engine.py:111-120`). Test validation checks those frozen sources, weights/checkpoint/data/policy (`engine.py:124-133`), then `validate_robustness_freeze` checks only the canonical recipe digest (`robustness.py:274-283`). The result manifest later records hashes for recipe and model weights, but not the robustness implementation source (`robustness.py:342-363`). Therefore a changed perturbation algorithm can still run against the same frozen recipe digest. Minimal fix: include `robustness.py` (and any perturbation helper modules) in an immutable source hash stored in the freeze and verify it before test evaluation; alternatively bind it in a separately frozen robustness manifest before the test run. This is a freeze-integrity gap, not evidence that prior predictions were changed.

Robustness checks otherwise follow the intended boundary: random, time-block, and related-group masks are intersected with the original input mask and applied only to `window()` inputs; `target()` delegates directly to the clean base data (`robustness.py:147-174,223-270`). Count noise is limited to count data, and hidden/unobserved inputs are zeroed before normalized model input (`robustness.py:175-192`). Related groups are ranked using only the training prefix/reference and training node mapping (`robustness.py:86-124`). Jitter candidates are first filtered on true event bins `<= origin` before applying ±1 jitter; shifted events are then constrained back to the current history window (`robustness.py:242-253`), avoiding future-event leakage. The test-only evaluator checks the test split, normal freeze, exact recipe digest and unchanged before/after parameter hash (`robustness.py:286-363`).

One narrow assumption: block draws treat adjacent sorted rows as adjacent prediction origins. The formal engine emits stride-one origins by default (`engine.py:25-29`), which satisfies this. `_validate_pairs` rejects duplicate origins but does not require consecutive origins; if future tooling supplies gapped/strided windows, the resampler may call nonadjacent times a block. Either keep the formal stride-one contract explicit or reject/segment gaps in `_validate_pairs` before using this bootstrap.
