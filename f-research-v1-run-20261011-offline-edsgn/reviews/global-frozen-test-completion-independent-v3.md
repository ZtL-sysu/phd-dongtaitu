# Independent review: global frozen-test completion v3

Review scope: read-only metadata/source review plus CPU toy tests. No real NPZ payloads, checkpoints, model, GPU, or campaign outputs were opened. This review does not authorize test access or accept scientific results.

The v3 source is a narrow successor to v2: the case driver ID and its corresponding report-contract branches change from `case_v2` to `case_v3`; the remainder is byte-line-equivalent. Source SHA-256 is `6b4979738256b0ffe86dd30b94db6543c7ced3e578f88ca70410c0507d06a1c5`. The v3 test suite passes 31 cases locally under `dyg-cold`; fresh independent log SHA-256 is `1a5f1b5077c2550a51d53cc38c52da07d9ef17bccb7ed5e3b32c2b63920b4d`.

No blocker was found in the metadata closure path. `_load_queue` (line 267) rejects unknown drivers and weakens of each driver's scope/coverage/phase, duplicate IDs/paths, overlapping output directories, and output collisions while allowing shared pretest bindings. `_read_job_and_bindings` (line 364) requires the exact queued job path and ordered binding paths, strict JSON, a queue-ref acyclic binding, and exact equality between queued independent refs and the refs discovered in bindings and job sources. `verify_queued_job` (line 453) returns these hashes for the dispatcher's BEFORE snapshot and rechecks bytes. `verify_completion` (line 480) requires exact global job membership, status/returncode, original child UUID distinct from dispatcher ID, receipt alias byte equality, output-directory agreement, exact dispatcher BEFORE/AFTER equality, and all queue/binding/source hashes in BEFORE. It then compares closed output-tree membership and hashes to completion and dispatcher receipts and performs a final consumed-byte/membership fence.

Metadata contracts exist for graph_v8, prediction_v5, H2_v4, profile_v5, C06_v5, simple_v3, and case_v3. Graph v8 specifically requires both `oracle_accessed` and `oracle_npz_decoded` false and deferred analysis. Simple v3 checks method/seed/oracle/test-feedback, domain binding, and prediction/metric hashes. Case v3 checks fixed variant/seed/full-window policy, no oracle/target feed, teacher/retention parity flags, all three arms, semantic-proof line counts, evaluation manifest, and closure. Unsupported required drivers remain explicitly unaccepted by the module docstring rather than silently counted as closed.

Two limits remain visible for root disposition. First, tests exercise the graph receipt layout and simple/case extensions, but do not build a single seven-driver fixture or mutate every member of a multi-job completion; prediction/H2/profile/C06 report contract paths are not independently fixture-tested here. Second, graph-v8 and H2-v4 phase receipts expose only an origin count/report hash, not a phase-level full output hash map. The helper allows that omission for those two contracts; exact full output closure is still enforced through dispatcher principal hashes and completion output-file maps. If root requires every child phase receipt itself to carry a full map, these driver schemas need successors before claiming that stronger property.

The v3 test suite uses opaque fake NPZ bytes and the verifier contains no NumPy/Torch loading path. It checks graph oracle flags without decoding oracle content. The helper only proves path/byte/receipt closure and producer metadata contracts; semantic correctness still belongs to per-driver producer validation and root scientific review.
