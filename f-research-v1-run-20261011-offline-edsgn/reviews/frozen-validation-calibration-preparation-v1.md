# Frozen validation calibration staging v1

This is engineering preparation only. No checkpoint, actual data archive, model, GPU, optimizer, or calibration candidate replay was opened or run. The CLI is deliberately prepare-only and refuses to launch calibration.

`edsgn/staging/frozen_validation_calibration_v1.py` adds a small scoped adapter around the unchanged `edsgn/src/edsgn/calibrate.py` module references. It temporarily replaces only `validation_block_length` and `evaluate_batches`, restoring both in `finally`. The block callback invokes accepted `validation_dependence_v2.validation_dependence` on the full captured validation arrays, derives L/Hmax/horizons and N/F from `PreparedData`, and cross-checks them against `payload['task']`. The helper takes the maximum of history, horizon, and per-trajectory ACF length; censored/unidentifiable nonzero ACF or inadequate declared test support fails without capping. Test support is built only from split-origin metadata (`origins('test')`), without calling `target()` or inspecting target/mask arrays.

The first full `evaluate_batches(..., split='val', limit=None)` return is copied and written as `validation-predictions.npz` with predictions, raw targets, target mask, canonical pairs in `origins`, and scalar model `seed_id`. Existing calibration JSON retains the original B=1 grouped cost table, 12-candidate replay and selection code. A sidecar adds the dependence report and archive digest. For all-zero validation, the adapter records the external history-length preset and the helper labels quality as unidentifiable; this is descriptive only and does not claim epsilon/quality selection.

Toy verification: `edsgn/tests/test_frozen_validation_calibration_v1.py` — **5 passed**; `py_compile` passed. The fixtures instantiate real `PreparedData` objects and the expected `payload['task']` shape, but use only in-memory toy arrays and a fake evaluator. The tests cover payload/shape cross-check, metadata-only test support, all-zero external history, unavailable ACF failure, callback restoration on failure, full-validation capture/NPZ scalar seed, output receipt, and the canonical stage-gate fail-closed check. Log: `logs/frozen-validation-calibration-toy-v1.log`.

## Execution boundary and remaining acceptance

The current canonical ledger is P2 `passed/pass`, P3 `running`, P3A `pending`, P4 `pending`; therefore this preparation cannot pass its required P2/P3/P3A/P4 authorization. No real invocation was attempted. `validate_preflight` is a pure fail-closed check and requires a root-accepted epsilon record, exact 12-row queue, empty resource locks/process scan, and remaining cumulative 72-hour budget, but the staging file does **not yet** acquire/release both production locks, query the live owned-process scanner/aggregate ledger itself, or write a whole-wall receipt. Actual calibration remains blocked until root accepts the adapter and a separately guarded execution wrapper wires those operational controls.

The original module exposes no public callback injection API; this staging adapter relies on temporary module-level replacement within one process. It does not change candidate scoring, the cost table, selection rule, model, or training. The toy test confirms restoration on failure, not thread safety; do not run concurrent calibration and adapter code in one process. The archive/sidecar are written only after the original calibration returns; a process interruption between original `calibration.json` creation and sidecar write leaves an intentionally incomplete immutable run that requires a new output directory.
