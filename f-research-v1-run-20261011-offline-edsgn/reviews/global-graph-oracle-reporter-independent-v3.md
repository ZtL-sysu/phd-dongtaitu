# Independent review: global graph oracle reporter v1

**Verdict: acceptable as a CPU-only reporting prototype after global closure; one narrow metadata-type hardening remains. This does not certify an actual replay or scientific result.**

I reviewed `edsgn/staging/global_graph_oracle_report_v1.py` against `protocols/global-graph-oracle-report-authority-root-design-v1.md` and the unchanged global completion verifier. The reviewed reporter SHA-256 is `84b6a1f4a434ebca33dcafb773acbb7246998e71987b3503e4c3ce6013f9f47b`; test SHA-256 is `b3324ba8b216f856c50fa78e1dc88595b0e519962b6bcf7730add461bc2c37a7`; completion verifier SHA-256 is `59b3d529efa76dc475448b3eccf88529a5ab12cc7ade53913f66d46b7a3850af`.

The decode order is correctly gated. The reporter checks the executing source bytes, then calls `verify_completion`; before opening any NPZ it verifies the root-attested completion, the frozen queue/job bindings, authority membership and hashes, exact sorted trajectory/oracle mapping, collection fingerprints, graph report fingerprints, and consumed bytes. It performs another consumed-byte fence before decoding. Its CPU toy test explicitly blocks `np.load` when completion is rejected. Prediction output and trace are decoded only after the same closure fence; trajectory metadata is read without materializing `raw_values`, whose NPY header supplies `(T,N,F)`.

The dimension check distinguishes forecast horizons from features: `predictions` must be `[origins,H,N,F]`, match target and mask shapes, have `H == hmax`, and match source `N` and `F == raw_values.shape[2]`. The fixture uses `H=7`, requested horizons `[1,3,7]`, and `F=1`, and the source checks those independently. It enforces exact chronological test origins, model-to-trajectory seed alignment, full compact-trace coverage, `input_time_index == origin-history+1+step`, and no input index beyond origin. The graph7 abrupt/gradual transition formula and directed `P>0` support are preserved. The report emits candidate IDs and aggregate intersection/difference counts, not oracle matrices or raw target values, and labels detailed alignment as sampled rather than full-window recovery.

After serialization it rechecks consumed inputs, collection membership, source hashes, global completion, and exact output-directory membership and hashes. Output creation is exclusive, and a failed run preserves its partial artifacts. The nine supplied CPU fixtures pass, covering closure-before-decode, successful toy alignment, abrupt/gradual boundaries, mapping rejection, exclusive output, source pins, collection TOCTOU, and final report/alignment mutation.

One narrow hardening remains before relying on malformed-authority rejection: authority `trajectory_seed_id` is compared to the decoded integer seed but is not itself required to have exact type `int`; JSON `true` compares equal to integer `1` in Python. Require `type(source["trajectory_seed_id"]) is int` alongside the existing exact `dataset_index` check. This does not alter the valid toy result or indicate an observed data mismatch, but closes an avoidable schema ambiguity.

I also rechecked ordinary admission's byte-identical checkpoint path handling. A missing execution-copy path now becomes `AdmissionError`, and a dedicated fixture covers it; the ordinary admission tests pass 15/15. The helper SHA after that repair is `7e265b84d33a98c16032ed152ab6f3668fd1d6ddb7a6d0193ab5de0eada24b48`.

All checks used local Conda `dyg-cold`, CPU toy fixtures, and metadata/source inspection only. No real dataset, model, checkpoint payload, oracle archive, GPU, training, or test evaluation was opened or run. This is an engineering-only source/toy review; actual oracle reporting, global experiment claims, and scientific conclusions remain pending.
