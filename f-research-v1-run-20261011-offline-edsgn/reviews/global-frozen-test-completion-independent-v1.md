# Independent review: global frozen test completion v1

**Verdict: needs a narrow repair before treating this helper as proof that every listed job has an independent output set.** The helper, dispatcher v8, and the five driver contracts otherwise align on the tested metadata path. This is an engineering-only review: no test arrays, checkpoint payloads, oracle inputs, model, or GPU were read or run.

The tested sources match the requested hashes: `global_frozen_test_completion_v1.py` SHA-256 `d90476b02d530862673fb520316b3b52b0c81b34222a6dfc6a15f4c15ccf3e75`; its tests SHA-256 `5d4588292282a22abca583a7683eefc85f2664e8a057b389f2c32a6c48ea7402`; dispatcher v8 SHA-256 `b946169932699f5efad8ae187e5c42cf2e247ccf0c97c895c9103c21d7748998`. The five report contracts agree with the live driver receipts and output names: graph v8, H2 v4, prediction v5, profile v5, and C06 v5. Meta8's nested pretest binding refs are recursively collected, so policy/config/calibration-authority path/hash refs are included when present in the binding. Queue bytes are pinned into the binding, job bytes pin the binding, and each queued job is rechecked against that chain before dispatch.

The 12 provided CPU fixtures pass (`12 passed in 1.69s`, local `dyg-cold`, `PYTHONPATH=src;scripts;staging`, OMP/MKL threads 2). They cover queue/binding tamper, missing job, output mutation, report scope/count/split/oracle constraints, random child receipt identity, absolute child output ownership, and alias equality. The helper enforces a closed-world hash of each declared output directory and before/after source/input snapshots. The five live drivers' child receipt schemas are compatible with those checks, including profile's five repeats and H2's arm-output records.

One concrete gap remains: `_load_queue` checks job IDs for uniqueness but does not require unique `output_dir`, `job_spec_path`, report/principal paths, or alias paths across different rows. A CPU counterexample duplicated a valid queue row while assigning a new job ID, job-spec path, binding path, and alias; `_load_queue` accepted both rows with the same `output_dir`, report, and principal files. This can make one closed directory satisfy multiple queue entries. Before calling the closure complete, reject cross-row collisions at least for output directories, job specs, aliases, and all declared principal/report paths; also reject duplicate binding paths across rows unless a deliberate shared-binding rule is explicitly represented.

The helper's own module documentation correctly limits its claim: it validates closure of the jobs enumerated in the frozen queue, not completeness of the entire RP matrix, nor scientific validity. Global campaign acceptance still needs an independently frozen queue covering every required endpoint and separate scientific review of the resulting records.
