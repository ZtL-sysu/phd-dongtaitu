# DCRNN staging adapter audit v2

This is a standalone staging diagnostic; it does not register a package baseline or make a scientific/performance claim. It leaves v1 and the upstream snapshot unchanged. The upstream PyTorch snapshot is pinned at `d92490b808ba5c5be2f23d427d96e9a56b066d7f`, and its license is MIT. The v2 smoke records SHA-256 before/after for the author recurrent cell, encoder-decoder, utility function, LA configuration, README, and license; all match.

v2 keeps the author dual-random-walk DCGRU encoder-decoder and diffusion order 2. The common input adapter zero-fills masked values without adding mask/age/event quality channels. Count forecasts remain `softplus(logit) * output_scale`; `count_data=False` uses the shared signed transform `logit * output_scale + output_mean`. Inputs/outputs are reshaped at the adapter boundary only. Curriculum learning is disabled and labels are never passed.

The explicit `[N,N]` `fixed_training_prior` is registered as a persistent checkpoint buffer. On `load_state_dict`, the adapter rebuilds every author cell's non-buffer `_supports` from the just-loaded graph using the unchanged upstream `calculate_random_walk_matrix` AST and unchanged `DCGRUCell._build_sparse_matrix`; subsequent `_apply` carries supports to the selected device. Loading into a constructor initialized with a different graph was checked: the checkpoint graph replaced it, supports were rebuilt, and predictions matched a source model using that graph. The buffer makes graph identity part of the state dict, but upstream support tensors remain derived plain attributes rather than serialized tensor keys.

The source's author sparse conversion routine sorts COO indices but passes the original data array to the sorted indices. The test therefore checks the actual tensors produced by this unchanged author conversion, for both forward and reverse random walks, and confirms the two directional tensors differ on the asymmetric toy graph. This preserves upstream behavior rather than silently correcting the source math. If exact intended edge-weight alignment is required, that upstream conversion must be reviewed separately before claiming mathematical equivalence; no source edit or substitute implementation was made here.

Counters report calls, not eligible nodes/rows: `recurrent_cell_calls = (L+H)×layers`, `diffusion_conv_calls = 2×recurrent_cell_calls` (gate plus candidate per cell), `diffusion_support_order_applications = diffusion_conv_calls×2 supports×diffusion order`, and `readout_calls = H`. Forward hooks on toy cases matched the cell, `_gconv`, and projection call counts. For B=2, N=5, L=24, H=7, diffusion order 2: calls were 62 recurrent cells, 124 diffusion convolutions, 496 support/order applications, and 7 readouts.

Four CPU toy cases covered B=2, N=5, F=1/2, both count and signed output. All produced finite outputs and finite gradients for all parameters; parameter counts remained stable after materialization; same-seed construction was repeatable; different-prior checkpoint reload synchronized the graph/supports and reproduced predictions at absolute tolerance `1e-7`; CPU `_apply` moved all sparse supports. No data, optimizer, GPU, test predictions, or scientific metrics were used. Whole-process wall time is logged only as a resource diagnostic.

Outstanding integration work is real training-only prior construction, provenance checks and graph-state packaging in the training/evaluation launcher, plus an independent review of the upstream sparse index/data permutation behavior before any mathematical-equivalence claim. No actual dataset prior was constructed here.
