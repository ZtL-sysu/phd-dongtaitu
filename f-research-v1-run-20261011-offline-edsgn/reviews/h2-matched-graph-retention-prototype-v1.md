# H2 matched-graph retention CPU prototype

The new `edsgn/staging/h2_matched_graph_retention_v1.py` is a no-CLI staging prototype. Its interface accepts only a model, causal `x/mask/age/raw`, optional causal event priors, a policy, and an explicit teacher descriptor. There are no target, oracle, checkpoint, dataset-path, or split arguments. It rejects anything except eval-mode, no-grad, retention-enabled spiking V4 with the informative teacher and full reference policy.

For each call the same frozen in-memory model first runs the ordinary full-policy teacher. A passive instance hook records each step's actual graph action IDs, pre-initialization bits, selected support IDs/weights/valid bits, and model `c`. Each arm starts a fresh runtime through the original forward path. It still executes the original `refresh_graph` so candidate generation/scoring/counters are real; then it substitutes the teacher's graph and computes only the prescribed pending-retention signal. The original clock, prior events, state update, readout, prediction feedback, and one-time pending/spike consumption remain in their model order. A `finally`-restored hook ensures the model method is restored if a replay errors.

Informative uses teacher `-beta*c`, cyclic shuffling uses the original within-batch cyclic `c` permutation, constant uses `log(.9)`, and reset uses `-80`. Every mode forces log retention to zero on first initialization, so first-refresh `g=1`. The arm hook verifies the pending-retention state before refresh matches the teacher and that graph/state action IDs and initialization history are unchanged. It then overwrites supports, weights, valid bits, and pending log retention while retaining the scorer's actual candidate work and counters. The returned graph loss is therefore a discarded-candidate scorer diagnostic, clearly flagged as unusable for objective/accuracy interpretation.

The probe checks informative prediction/graph-loss parity at `1e-6`, final membrane/spike/pending-retention state at `1e-5`, exact step graph/state IDs/supports and counters, and parameter hashes before/after. CPU toy tests passed **6/6** across three fixed seeds and two batch slots. They verify exact matched supports/weights/valid bits and actions for all four arms, first `g=1`, one-step consumption, expected constant/reset/shuffled signals, informative teacher reproduction, nontrivial retention-arm prediction changes, mode/descriptor/policy rejection, and parameter/method immutability.

Validation used local Conda `dyg-cold`, explicit `PYTHONPATH=<run>\edsgn\src;<run>\edsgn\scripts;<run>\edsgn\staging`, and OMP/MKL threads 2. `py_compile` passed; pytest reported 6 passed. See `logs/h2-matched-graph-retention-toy-v1.log` and `.json`.

Scope and limits: CPU toy functionality only; no real data, checkpoint, oracle, test collection, GPU, optimizer, or replay was accessed. This does not implement a frozen test artifact, paired statistical analysis, source/data/checkpoint freeze, or P3A/P4 gate. A future operational H2 probe still needs those protections. Teacher generation plus discarded scorer work adds overhead, so none of these timings may be presented as ordinary inference speed or energy. The same-step graph is held fixed by construction; the arms' own prediction/state trajectories can differ and are the intended intervention outcome.
