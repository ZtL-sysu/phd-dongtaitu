# Independent review: H2 matched-graph retention prototype v1

**Verdict: acceptable as a CPU engineering prototype only; not an operational experiment or scientific evidence.** The core intervention matches the protocol on code inspection and existing toy tests. One reporting bug must be fixed before any consumer interprets parity status.

Protocol source: `protocols/h2-matched-graph-retention-probe-v1.md` (SHA-256 `2e48dacb23540b20f8d8f5cf9dcf3818cc81b4aa5774c9282eb5adcca6f655ff`). Reviewed implementation SHA-256 `33978777d43cb6da28f2a09d4d8bd1a4629f305a0db153f72916ee4b91adeac3`; tests `6944af8d6424751f378c1a170f945e91313b03bc8e2504f0d952dbb6aa1fa7fa`; existing toy evidence JSON `d628c0ea5b864ad3885580ea3b5b3653eb256e8598dabbf9222d7058f390a642`. Reran the focused local-Conda CPU suite: **6 passed**. No targets, real data, checkpoints, GPU, or optimizer were used.

The probe takes only causal model tensors plus optional `event_priors`; its Python signature has no target/oracle/dataset arguments. It requires eval/no-grad V4 with informative retention and full policy, hashes model parameters before/after, and restores the `refresh_graph` hook in a `finally` block. Teacher capture records action rows, initialization bits, support IDs, weights, validity, and `c`. Each fresh arm executes the real graph/scorer path, then substitutes the teacher graph and its prescribed retention update; the original candidate loss is retained only as a flagged discarded diagnostic. Initial refresh sets log-g to zero, and the existing state update consumes pending log-g and clears it. Tests verify paired IDs/support/weights/validity, first g=1, pending consumption, nontrivial control effects, parameter/method restoration, and informative output/final-state parity when that arm is run.

**Required fix:** `informative_teacher_parity = informative is None or True` reports success when the caller omits the informative arm. The default all-arm tests do execute `_assert_informative_matches` first, so those results are checked; however, the public `arms` option permits e.g. `arms=("shuffled",)`, where parity is untested but marked true. Before use, require informative to be included or report `None`/`not_run`; record pass only after the actual assertion succeeds. Add a regression for omitted informative arm.

Operational caveats: `H2TeacherDescriptor` is caller-supplied metadata, not provenance evidence; the prototype cannot prove that `x/mask/age/raw/event_priors` came from an allowed split or that the same frozen checkpoint/policy/source/data was used. The docs correctly state these freeze/gate protections are not implemented. Candidate work is executed in each arm and its graph loss is discarded; no timing/energy inference is valid. The existing tests check matched relation/action tensors but do not explicitly assert equal candidate/scorer counter totals across arms. These limitations keep the prototype below P3A/P4 and prevent it from supporting H2 claims.
