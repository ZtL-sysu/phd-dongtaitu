# Independent review: frozen graph/state diagnostic v1

Scope: read-only source and toy-test review of `edsgn/staging/frozen_graph_state_diagnostic_v1.py`, its preparation note, model trace path, and CPU toy checks. No real dataset arrays, test values, checkpoint, GPU, or optimizer were accessed. The only execution was the staged unit test with the local `dyg-cold` Conda interpreter.

## Findings

**Launch blocker — detailed trace volume has no preflight estimate or disk guard.** The runner captures four full membrane tensors per history step: `u_before_clock`, `u_after_clock`, `state_u_before_update`, and `state_u_after_update` (`frozen_graph_state_diagnostic_v1.py:140-150, 175-195`). For the declared N=64, `d_total=64` setup, each is `[64,2,2,16]` = 4,096 scalars. A full four-trajectory test replay has 8,056 origins × 28 steps = 225,568 rows, so just those four fields serialize 3,695,706,112 numeric scalars, before spike/reset snapshots, graph supports, and metadata. Even a one-character scalar plus delimiter lower bound is about 7.4 GB uncompressed; actual JSON numbers are longer. Gzip does not substitute for a measured estimate, and the runner checks budget time but not free disk/output size. Do not launch the full replay until a same-shape CPU toy serialization estimate and disk-space bound are recorded, or the detailed capture is reduced to a predeclared bounded sample while preserving full-origin predictions, raw metrics, counters, and TV.

**Major — oracle bytes are not rechecked after oracle loading/analysis.** The exact test+oracle collection is fingerprinted before inference and again after inference, before `_read_oracle_after_replay` opens oracle NPZs (`:308-322`). If a file changes between that fingerprint and opening/analysis, the result can be labeled with the earlier fingerprint. Recheck the collection after all oracle reads/analysis and before writing the final diagnostic, or hash/open from an immutable snapshot. Oracle arrays are otherwise kept out of model/policy execution: `engine.predict` receives only `x/mask/age/raw/events` (`engine.py:53-54`), and oracle reading begins after all origins, unchanged parameter hash, freeze revalidation, and the pre-oracle collection check (`diagnostic:272-322`).

**Moderate — resource-gate implementation dependencies are not part of the diagnostic freeze.** `main()` imports `aggregate_budget.aggregate` and `_owned_model_processes` from `candidate_gpu_fullpath_probe_v2` (`:389-394`) to enforce the cumulative budget and process barrier. `frozen_diagnostic_extras()` binds only this diagnostic source and `model.py` (`:60-73`); the extra gate-helper source bytes are neither frozen nor rechecked. Bind their SHA-256s in the accepted freeze and verify before the guard runs. Otherwise a changed guard helper could alter whether the two exclusive locks/process/budget checks actually protect the run.

**Moderate reproducibility defect — toy test import path requires undocumented `PYTHONPATH`.** The test computes `ROOT=parents[2]`, then prepends `ROOT/staging` and `ROOT/src` (`test_frozen_graph_state_diagnostic.py:9-11`), but the files live at `ROOT/edsgn/staging` and `ROOT/edsgn/src`. Running pytest from the run root or `edsgn` failed collection with `ModuleNotFoundError: frozen_graph_state_diagnostic_v1`. With explicit `PYTHONPATH=<run>\edsgn\src;<run>\edsgn\staging`, the local Conda run passed **5 tests**. Fix the test paths or record the required environment in the test command/log.

## Semantics checked

- The stage gate requires P3A=`passed` and P4=`running` (`:76-80`). Both `logs/model-resource.lock` and `logs/offline-phase-wall/campaign.lock` are acquired with exclusive create; the owned-process scan occurs after acquisition, the phase receipt is finalized in `finally`, and only locks created by this process are removed (`:400-434`). `budget_guard` checks the 72-hour aggregate and coverage before replay and at each origin (`:407-412,272-273,335,355`). These controls are present, subject to the unbound helper-source issue above.
- Full test origins are required and compared against the prepared split's complete origin list (`:256-263`); inference is `@torch.no_grad()`, `model.eval()`, and no optimizer path is present. Parameter hashes are compared before/after replay and `engine.validate_freeze` is run again (`:265,305-309`); that validation rechecks checkpoint and package source bindings.
- The diagnostic's full collection fingerprint includes each test NPZ, corresponding oracle NPZ and optional collection manifest without decoding arrays (`:41-58`). Oracle matrices are not passed to the predictor or scheduler. A post-oracle fingerprint check is still needed for TOCTOU closure.
- `expected_transition` uses retained-bin indices: abrupt changes switch at `t >= switch_index`; gradual interpolation uses `(t-switch+1)/length` (`:109-121`), matching `prepare.py:534-539` and retained-index metadata (`prepare.py:550-566`). Trace `input_time_index` is the observed history bin; saved `origin_relative_to_switch` is the forecast-origin offset. This preserves pre-switch history and transition placement. Prediction/metric outputs are not themselves a binned recovery curve; the per-origin predictions and relative-origin metadata allow later derivation, but the preparation note correctly avoids claiming a recovery result or inventing recovery bins.
- `c` is the model's signal only for actual graph refreshes; trace stores `None` when there are no graph rows (`model.py:552`). Initial graph construction has `c=0` by the declared model rule, while uninitialized `row_tv` is separately null (`diagnostic.py:173-185`, plan `implementation-plan.md:238,556`). This distinction is scientifically appropriate.
- Pending `log_g` is recorded before/after clock, after graph refresh, and around the selected state update (`diagnostic.py:142-195`). Model order is clock decay/reset consumption, graph refresh, then state update (`model.py:211-216,524-532`). `exp(pending_log_g)` is the value used at update; retention multiplies only old slow-neighbor state and the pending value is then cleared (`model.py:483-492`). Reset mode's `log_g=-80` means numerically near-zero retention (`exp(-80)`), not mathematical exact zero; the report should preserve that wording.
- `row_total_variation()` has no explicit validity-mask argument (`diagnostic.py:98-107`), but the current model writes every selected support slot as valid and uses fixed `k` top-k supports (`model.py:410-435`); uninitialized rows are marked null before invoking the helper (`diagnostic.py:163-185`). I found no current padding/zero-node misalignment under that invariant. Add a toy with node ID 0 plus an invalid padded slot (or assert all slots valid/distinct) so a later variable-size support implementation cannot silently miscompute TV.
- `component_host_ms` is embedded in trace rows from the model trace (`diagnostic.py:201-210,292-303`). These are instrumented per-step timings during a full diagnostic and must not be represented as an efficiency profile or energy measurement. There is no energy attribution in the runner; the report would be clearer with an explicit `timing_scope=diagnostic_overhead_not_profile_or_energy` field.
