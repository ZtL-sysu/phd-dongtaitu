# Independent review: global completion repair and oracle reporter

**Global completion v1 repair: pass for the previously identified cross-job path-collision defect. Oracle reporter v1: needs one final membership-fence repair.** This is source/CPU-toy evidence only; it does not analyze the real test collection or establish any scientific result.

The global completion helper is SHA-256 `59b3d529efa76dc475448b3eccf88529a5ab12cc7ade53913f66d46b7a3850af`. The prior collision counterexample is addressed: `_load_queue` now rejects repeated job-spec, output, report, principal-artifact, and alias paths, ancestor/descendant output overlap, and aliases within an output tree. It explicitly permits shared pretest execution bindings, appropriate for a shared immutable plan. Its updated fixtures exercise those cases. The merged CPU suite for both helpers passes: **26 passed in 3.83s** under local `dyg-cold`, `PYTHONPATH=src;scripts;staging`, OMP/MKL threads 2.

The reporter source matches SHA-256 `ea944f8e26ac947b5d4caf82ae4af04dd10786636eefd0042ee32ecbab14287b`; design SHA is `b9fc5195eaf99538e28b3a686fb1d46b22c516b70f9ad0d8be9b981526e14534`. Its sequencing is sound through initial decode: it checks the executing reporter/completion source pins, calls the unchanged global completion verifier, verifies the authority/queue refs and consumed bytes, matches authority rows to all graph-v8 jobs and sorted trajectory/oracle members, checks graph report collection fingerprints and completion output hashes, then takes another consumed-byte fence before opening prediction, trace, trajectory, or oracle NPZs. It has no torch/model/checkpoint imports. The toy tests confirm the verifier is called before any NPZ load and verify the abrupt boundary (`retained_index < switch`) and gradual alpha `(retained_index-switch+1)/length`. It uses the recorded `input_time_index`, checks history-step/origin alignment, and labels detailed support alignment as sampled rather than full-window edge recovery.

The remaining blocker is that the final barrier rehashes each authority-listed trajectory/oracle and re-verifies global completion, but does not recompute full dataset-directory membership against the saved graph fingerprint. I independently reproduced this using the existing temporary CPU fixture: during oracle alignment, a callback added a new file under the toy dataset root. `analyze_global_oracle_report` returned success, and the emitted `collection_fingerprint` omitted that late member. Thus a collection membership change after the initial fingerprint check can pass the purported final fence. Before accepting reporter output, recompute `_collection_fingerprint(dataset_root)` at the post-serialization barrier for every graph job and require exact equality to both the initially frozen map and graph report fingerprints; this should catch added, removed, renamed, or modified members.

The authority scope remains limited to the graph-v8 jobs enumerated by its queue. Neither its report nor this review proves completeness of the full RP matrix, acceptance of an actual root authority, or any hypothesis/result. No actual NPZ, oracle, target, checkpoint, model, or GPU was accessed in this review.
