## The six v1 findings

1. **Weighted window-history missingness denominator — repaired.** `_window_coverage` constructs each retained bin's complete-origin history multiplicity, then reports total window slots, observed positions before/after, total missing fractions, newly hidden observed positions, and the incremental removed fraction over original observed positions (`split_history_robustness_v2.py:88-135`). These calculations use the original `data.input_mask`, not targets or prediction outcomes. The requested union-time rate remains a separate field. This matches the C06 distinction between union rate and replay-weighted history coverage.

2. **Mask-dependent QC summary — repaired.** After final block visibility is installed, v2 recomputes clean-zero observed positions, noisy-zero visible positions, eligible count-noise positions, effective missingness, hidden positions, and final mask digest against the final input mask (`:301-326`). The inherited noise is still generated by `edsgn.robustness` under the preregistered discrete `{-1,0,+1}` count-noise rule and then hidden cells are zeroed; event jitter remains inherited and target delegation is unchanged (`robustness.py:195-239, 254-289`; preregistration `protocols/robustness-count-noise-jitter-preregistration-v1.md`). The toy suite checks the prior zero-count mismatch, unchanged target/mask, normalized visible values, hidden zero fill, and inherited jitter/noise behavior.

3. **Freeze must bind the executing wrapper — repaired.** Both single and bundle freeze helpers require the supplied path to resolve exactly to `Path(__file__).resolve()` before hashing it (`:352-365, 390-399`). Validation reconstructs the expected extra from that same executing module and compares the complete metadata object. The tests reject an unrelated in-root wrapper. This binds the staged code path; actual evaluator integration must call the validator before constructing/replaying each view.

4. **Transitive `robustness.py` SHA — repaired.** Each frozen row stores `_sha256(robustness.__file__)` alongside the wrapper SHA, and validators recompute it through the exact expected metadata path (`:216-224, 352-374, 405-430`). Tests mutate the dependency bytes and reject validation. The full engine-level source/data freeze must still remain active at replay.

5. **Typed trajectory index — repaired.** `_exact_nonnegative_int` rejects bools, strings, floats, and negative values; split-origin arrays must also have integer dtype (`:39-55, 65-67, 251-255`). Bundle construction fixes indices to the deterministic zero-based enumeration and rejects an incomplete/nonconsecutive list (`:174-185`). Tests cover bool, negative, float, and string indices.

6. **Strict domain manifest and collection ordering — repaired for the staging identity contract.** The manifest is strict UTF-8 JSON with duplicate-key and nonstandard-number rejection, then exact canonical structural comparison against a manifest reconstructed from the supplied prepared data (`:193-211`). Its schema includes dataset identity, split bounds, node IDs digest, source trajectory seeds/input-mask digests, complete origins/history union, and ordered trajectory indices. Bundle extras require index order `0..n-1`, and bundle validation recomputes the entire ordered trajectory list (`:142-191, 390-438`). Tests reject wrong schema, numeric type, trajectory-range edit, duplicate keys, and truncated bundle. Reversing distinct seed/mask rows would change the ordered expected manifest and fail validation.

## Remaining integration boundary

The domain manifest intentionally binds metadata and source input-mask identity rather than every raw prepared-array byte. The implementation author's v2 review correctly states that the existing engine dataset/preprocessing fingerprint must remain mandatory. At integration, the caller must bind the exact ordered collection fingerprint and pass the same canonical dataset list to freeze creation, view construction, and validation; the staging bundle alone cannot prove that a caller did not supply a different but metadata-equivalent collection. No real domain manifest or canonical collection binding was reviewed here.

Accordingly, the six v1 blockers do not prevent accepting v2 as an isolated engineering prototype. The missing canonical freeze/evaluator integration and absent real manifest remain hard blockers for any actual P4 replay or robustness claim. The self-review `reviews/split-history-robustness-independent-v2.md` is useful implementation evidence but is not counted as this independent audit.
