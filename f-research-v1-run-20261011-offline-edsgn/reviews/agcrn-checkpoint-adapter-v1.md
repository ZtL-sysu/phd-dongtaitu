# Prospective AGCRN cell-checkpoint adapter v1

The external, staging-only wrapper and focused CPU tests are ready for review. Root reported that both B2 and B1 email AGCRN jobs OOMed at the shared allowance, while the episode AGCRN job remains unstarted. This receipt does **not** claim a GPU memory reduction or authorize a production run; it establishes exact-family CPU functionality/parity before any possible integration.

`agcrn_checkpoint_adapter_v1.py` is a context manager with `enabled=False` by default. When enabled it temporarily wraps each existing `network.encoder.dcrnn_cells[i].forward` method and delegates gradient-enabled training calls to `torch.utils.checkpoint.checkpoint(original_bound_forward, x, state, node_embeddings, use_reentrant=False, preserve_rng_state=True)`. The wrapper does not replace cells, copy their weights, reimplement the recurrent loop, alter the state dict, or modify upstream source. Call-time guards use the outer model's `.training` flag and `torch.is_grad_enabled()`; eval and no-grad invoke the exact saved bound method. Original instance methods are restored in a `finally` block.

CPU verification used integrated `AGCRNForecast` adapters with B=2, N=5, L=6, H=3, two official recurrent layers, F=1 and F=2, and both signed and count-output modes. All **7 tests passed** in 4.31 pytest seconds / 5.86 seconds whole command. Tests compare prediction and graph-loss tensors, input gradients, every named parameter gradient and `None`-gradient pattern; outputs were exactly equal, all compared gradients passed `rtol=1e-6, atol=1e-7`, and all gradients were finite. Additional checks verify eval/no-grad bypass, default-disabled behavior, unchanged state-dict keys/values, reload prediction equality, and restoration after an exception. No real data, CUDA, or optimizer was used.

This is a prospective training-time memory/computation tradeoff. Checkpointing will recompute each recurrent cell during backward; it may increase wall time. Current pinned AGCRN cells have no dropout or BatchNorm. RNG preservation is enabled. If upstream later introduces BatchNorm, its running-stat update could occur twice during recomputation and requires explicit handling before use.
