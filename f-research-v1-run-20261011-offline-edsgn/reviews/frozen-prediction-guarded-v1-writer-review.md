**Writer result: CPU engineering fixtures pass; independent root acceptance pending.** The bridge is a new staging driver and does not modify `edsgn/src`, engine, controller, or existing replay drivers.

It requires `--split test`, a full-protocol checkpoint, sibling immutable `test-freeze.json`, verified at-launch binding, exact bound dataset path/fingerprint, P2/P3/P3A passed/pass with every P3A input/evidence hash checked, and P4 running. It verifies policy digest against the validation freeze; periodic/random also require the bound blind-reference helper source/rule fields and install its adapter. Full/adaptive remain on the original engine policy path. It invokes only `engine.evaluate_run` with no limit, batch size one, fixed FP32, and compares serialized ordered origins/prediction/target coverage to the full test origin list. Before the call, inputs are normalized with checkpoint training statistics: synthetic uses the existing frozen stress normalizer and exact `prepare.apply_normalizer` parity; other collections must already match checkpoint mean/std/residual scale. Engine prediction receives only inputs/mask/age/raw/events; targets are consumed by the evaluator after prediction for scoring.

The bridge verifies both resource leases, invokes the cumulative 72-hour guard before work, before each actual `engine.batch_at`, and once after serialization plus source/data/freeze/pipeline fences. It preserves outputs on failure, records a failed phase receipt, releases acquired leases, and emits completed-receipt `outputs` entries with absolute paths and SHA-256 digests for every output. The receipt command includes `--checkpoint` and `--split test`, matching `paired_statistics_shared_v4._validate_test_artifacts`' contract.
