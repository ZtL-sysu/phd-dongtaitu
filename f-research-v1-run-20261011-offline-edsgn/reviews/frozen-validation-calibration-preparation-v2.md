# Frozen validation calibration staging v2

V2 is an additive production-wrapper preparation; v1 and its evidence are unchanged. No calibration, model forward, optimizer, GPU, checkpoint load, or actual data archive access was performed. CPU tests use only in-memory toy `PreparedData`, mock receipts, and temporary files.

The CLI is `edsgn/staging/frozen_validation_calibration_v2.py`. It requires explicit checkpoint, config, registered queue, root-accepted epsilon evidence, at-launch input binding, output path, and device. Its preflight requires canonical P2/P3/P3A `passed/pass`, P4 `running`, current hash-bound P3A inputs/evidence, 1–12 unique queue entries, a root-accepted validation-only epsilon record bound to checkpoint/config/queue/dataset, a hash-verified baseline-variability evidence file also hash-bound by P3A, requested metric/horizons, and metadata-only independent test-origin support. Current ledger state is P2 passed/pass, P3 running, P3A pending, P4 pending, so this run is correctly blocked before any calibration call.

After preflight, the wrapper reuses `simple_baseline_freeze_v1` launch helpers for the shared `model-resource.lock` and `offline-phase-wall/campaign.lock`, owned-worker scan, cumulative-budget coverage/72-hour stop-loss, periodic phase receipt update, token-owned receipt finalization, and lock release. It snapshots SHA-256 over the checkpoint, config, queue, epsilon and baseline evidence, at-launch binding, dataset source files (hash-only), package/upstream implementation sources, accepted gate inputs/evidence and helper sources. It verifies the snapshot after execution and records before/after digests plus the unchanged model parameter hash in the whole-phase receipt. A budget checkpoint occurs before each original validation evaluation/candidate replay and at phase completion.

The unchanged `calibrate_run` retains B=1, its measured device-specific grouped cost table, registered candidate replay, scoring, and selection, with a maximum queue size of 12. Scoped callbacks are restored in `finally`; a split-binding callback supplies only preloaded `validation_seed*.npz` partition files, and rejects other splits/datasets. The wrapper requires checkpoint payload task metadata to agree with validation `PreparedData` shape and requires all floating checkpoint tensors to be FP32. It captures the first full unbounded validation evaluation, verifies canonical full-origin order and recomputes targets/masks only from those validation `PreparedData` objects, and writes raw predictions, targets, masks, origins, scalar model seed, required horizons, feature labels, pooled per-horizon/per-feature MAE/RMSE/counts, candidate rows and dependence diagnostics. Test support is independently derived from each `test_seed*.npz` `metadata_json` member only; the toy proxy asserts no target/mask member is touched, and those metadata-derived counts must match the root-accepted epsilon record. It never calls `target()` on a test partition. The accepted per-trajectory ACF helper controls the block; unavailable dependence fails rather than being capped. The all-zero branch records the external history preset with non-identifiability.
