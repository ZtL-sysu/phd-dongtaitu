# P3 campaign auditor v1 — implementation self-review

This is a writer self-review of an inert batch-audit wrapper, not an independent review and not an experiment result. The wrapper does not start jobs. It checks six existing accepted queues and supports auditing already-completed training phases only.

The metadata preflight verified 80 unique queue jobs across the accepted 8/10/16/6/16/24 sets. It checks current queue and root-acceptance hashes, acceptance input pins, config hashes and queue/config task identities. Queue schemas differ; the implementation handles direct queue pins and queue pins inside acceptance evidence maps, and does not assume a fixed number of external phase inputs.

For a completed receipt, it requires successful training status, matching queue identity, in-root output directory, current hashes for every declared phase input and output, the seven training principal artifacts, a full-protocol summary/manifest, explicit `test_accessed=false` and `stop_loss_reached=false`, positive train/validation window counts, a matching checkpoint hash, and a full output-directory snapshot. It emits pending and failed jobs separately. Existing v3 numeric reports are eligible for reuse only when config/run/model-seed identity, phase artifacts, checkpoint, source hashes, recomputed windows, required horizons, launch binding, and current binding verification agree. New numeric auditing is restricted to split-separated train and validation NPZs; a combined chronological NPZ is rejected before the numeric auditor can open targets. The aggregate output is exclusive and labels itself a development validation audit, with no root acceptance, phase pass, five-seed, test, or scientific claim.

CPU-only artificial fixtures cover a valid completed row through a numeric stub, missing-receipt pending status, phase-output hash tampering, and combined-NPZ rejection. The actual queues were checked metadata-only. No actual campaign audit, model/checkpoint load, prediction/target array, GPU, or training process was run.

Remaining boundary: the wrapper has not audited the live 80-job set. Running it later will read validation arrays only for new audits backed by split-separated archives; current combined email/MOOC/episode NPZs require a previously saved compatible report or will be reported failed without opening their target members. Its output is an aggregation of saved validation checks, not root numeric acceptance or pipeline advancement.
