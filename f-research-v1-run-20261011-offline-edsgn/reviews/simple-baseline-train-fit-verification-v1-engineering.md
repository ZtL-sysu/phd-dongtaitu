# Train-only simple-baseline fit verification: engineering preparation

This staging verifier independently rebuilds the legacy ridge sufficient statistics from `train` origins, using float64 Gram/RHS accumulation, the engine's complete H×F target-mask row rule, unpenalized intercept, `1e-3 * max(count, 1)` ridge, and the existing `1e-10 I` term. It reads the preserved coefficient only after the pre-P3 gate, checks shape/dtype/finiteness and coefficient differences, then independently recomputes persistence and frozen-linear outputs on all validation origins and compares saved targets, masks, origins, predictions, and per-horizon metric rows. It never calls the test split or modifies a coefficient.

The guarded entry point binds current source files, train/validation shard bytes and full collection membership, all legacy outputs, the current P2/P3 chronology and every passed-stage reference. It requires official `--before P3`, both model/campaign leases, the process scan and a complete under-72-hour aggregate budget; callbacks check leases, process state and budget during numerical loops and at the final serialization barrier. Receipts preserve UUID, whole-phase wall time, input-fence hashes and output hashes. Output directories are exclusive. Incomplete or mismatching verification artifacts remain available for root review rather than being silently replaced.

The CPU fixture suite passes **10 tests** (`logs/simple-baseline-train-fit-verification-v1-tests.log`). It exercises toy legacy parity, clean-mask row selection, validation-only loading, gate ordering, chronology rejection, source mutation, dual leases, foreign lease preservation, budget gaps, 72-hour stop-loss, and Python process detection with legal interpreter flags before model modules/scripts. Python compilation also passes.

This is engineering preparation only. No actual legacy coefficients, validation results, model/checkpoint, optimizer, GPU, or test/oracle values were accessed. The official validator was mocked in the CPU order fixture; the production before-P3 validator and guarded CLI were not run. The four real train-only reconstruction and validation-parity audits remain pending, as do independent review and root acceptance. For combined chronological NPZs, the loader may materialize held-out members; the verifier scores and inspects only train and validation origins. Hash fences cover train/validation source shards plus metadata, while whole collection membership is frozen.

Artifact/source hashes are recorded in [the machine-readable evidence](simple-baseline-train-fit-verification-v1-engineering.json). The core new files are [the verifier](../edsgn/staging/simple_baseline_train_fit_verification_v1.py) and [its toy tests](../edsgn/tests/test_simple_baseline_train_fit_verification_v1.py).
