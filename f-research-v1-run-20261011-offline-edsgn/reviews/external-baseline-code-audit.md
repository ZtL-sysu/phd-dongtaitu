# P2 external baseline code audit

## Implemented interfaces and verification

`edsgn.baselines.build_baseline(name, *, n_nodes, n_features, history, hmax, count_data, norm_mean, norm_std, output_scale, output_mean, **kwargs)` builds a module with `forward(x, mask=None, age=None, raw=None, policy=None, event_priors=None, return_trace=False)`. Every implemented model returns `predictions [B,H,N,F]`, differentiable `graph_loss`, `counters`, `trace`, `runtime`, and `intermediate`. The API consumes only training-fitted normalization metadata and historical x/mask/age; there is no target argument or calendar feature. Count heads use `softplus(logit) * output_scale`; normalization uses supplied train-fit `norm_mean/std` for autoregressive generated inputs.

The requested local Conda environment was used: `C:\Users\xhf\miniconda3\envs\dyg-cold\python.exe`, Torch `2.11.0+cu128`. `pytest edsgn/tests/test_baselines.py -q` passed (`2 passed in 24.16s`). Tests include forward/finite-gradient checks for LinearPredictor, CompactGRU, DGCRNAdapted, and the explicitly paper-derived SpikeSTAG path; external graph/SNN baselines cover `L=24,H=24`. No formal training, validation selection, or test evaluation was performed here.

## DGCRN: required adapted graph forecaster

- Paper: [Dynamic Graph Convolutional Recurrent Network for Traffic Forecasting (TKDD 2023)](https://dl.acm.org/doi/10.1145/3570928); author-linked [official PyTorch source](https://github.com/LakeChuan/DGCRN).
- Pinned snapshot: `sources/DGCRN`, commit `b9f8e40b4df9b58f5ad88432dc070cbbbcdc0228`. The root `LICENSE` text is MIT (SHA256 `5BDD61BB0A8A51DA3D9D2E0954B8CE9629B2DB06C6F24D1077079DD83D94A230`), while the same source's README header carries a CC BY-NC-SA license badge; preserve and resolve this repository-level inconsistency before redistribution. Reference files: `methods/DGCRN/net.py` SHA256 `F3112377747AE76CE9F0339C59556655DB7E251AC9ACE7FAFEA9C62CE3FF8037` and `methods/DGCRN/layer.py` SHA256 `6B490B188294ABD14361F7C152A25A36928CCDC7614126AEEA88114AB97361EC`.
- `DGCRNAdapted` retains learned node embeddings, hypernetwork-generated skew dynamic adjacency, dual directions (adjacency and transpose), DGCRM gates, recurrent encoding/decoding, and generated dynamic graphs at each observed/forecast step. It is a local translation of the cited layer equations, not the upstream traffic training program.
- Necessary task changes: historical inputs concatenate normalized values, validity, and log age (3F); static support is identity because there is no known fixed graph; decoder emits F counts, rolls predictions autoregressively to `hmax` (including H=24), and receives neither future labels/teacher forcing nor future time-of-day features. The original traffic code assumes one output channel, road support, traffic/time features and dataset/trainer interfaces; its source stack asks for old MXNet/TensorFlow dependencies, which were not installed. Dynamic adjacency remains dense `N×N` at each step, so its time/memory cost is quadratic; counters report graph calls and dense adjacency elements. Report this as an adapted graph baseline, and do not equate it with a directly run upstream benchmark.
- Equation-by-equation source mapping (this is a re-expression, not byte-for-byte imported code):

| Upstream code | Adapted code | Difference |
|---|---|---|
| `layer.py:gcn.forward`, hyper mode: `h←αx+γ A h`, concatenate depth states, sigmoid MLP | `_DGCRNGraphConv(mode="hyper")` | Same recurrence and layer stack; A is identity static support. |
| `net.py:step`: `filter = GCN_tg(hyper_input,A0)+GCN_tg_1(hyper_input,A1)`; `u=tanh(α*emb1*filter1)`, `v=tanh(α*emb2*filter2)` | `_DGCRNHyperPair`, `_DGCRNCell.forward` | Same two independent hyper branches per filter and learned node embeddings. Adapter's `static_support` is identity and it uses Parameters instead of `nn.Embedding`; initialization therefore differs. |
| `net.py:step`: `A=relu(tanh(α*(uvᵀ−vuᵀ)))`; row-normalize `A+I` and separately `Aᵀ+I` | `_DGCRNCell.forward` | Same skew adjacency and two row normalizations; identity support transposes to itself. |
| `layer.py:gcn.forward`, RNN mode: `h←αx+β A_dyn h+γ A_static h` | `_DGCRNGraphConv(mode="rnn")` | Same diffusion, batched vectorized over B. |
| `net.py:step`: reset/update/candidate GCNs on dynamic forward and transposed supports; `h←z*h+(1−z)*candidate` | `_DGCRNDirectionalGRU.forward` | Same gate equations and separate forward/reverse graph convs. Encoder/decoder cells remain separately parameterized. |
| `net.py:forward`: encoder for configured `seq_length`, zero start, then decoder input `GO + future tod`; optional curriculum sampling replaces input with true prior output | `DGCRNAdapted.forward` | Encoder loops actual `history`; forecast loop uses `hmax`, starts at zero, then feeds back prior predicted counts/mask=1/age=0. No labels/calendar are accepted. Original `fc_final` is one channel; adapter head is F channels and uses train-fitted nonnegative raw-count conversion. |

The upstream constructor defaults include hidden=64, node_dim=40, hyperGNN_dim=16, middle_dim=2, tanhalpha=3, and diffusion weights (0.05,0.95,0.95). Adapter defaults preserve these structural sizes/coefficients except gcn_depth comes from the wrapper (default 2); parameter counts must be logged because input-width and output-head changes alter capacity. The source's extra `lin1/lin2` embedding projections are unused in `step` and intentionally absent.
- Main comparability risks for P3: default hidden width and graph depth determine parameter count; budget-match/tune on train/validation under the same ≤12 pilot cap, disclose parameter and dense-graph costs, and verify full H24 raw-unit scoring. Identity support avoids introducing unavailable side information but changes original road-graph semantics.

## Recent spiking forecasting comparator

### Required executable comparator: Microsoft SeqSNN iSpikformer

- Paper: [Efficient and Effective Time-Series Forecasting with Spiking Neural Networks (ICML 2024)](https://arxiv.org/abs/2402.01533); paper §3.2–3.4 and appendix §A.3 specify the input encoders, SNN models and forecasting implementation details. The paper itself links [Microsoft's official SeqSNN code](https://github.com/microsoft/SeqSNN).
- Snapshot: `sources/SeqSNN`, commit `15cbacb123362c97c0aa0f6f861c18f4f77e3e8f`, MIT license. The unchanged iSpikformer backbone is in `SeqSNN/network/snn/ispikformer.py`; relevant unchanged components are `module/encoding/spikingjelly/encoder.py` and `module/spike_attention.py`. The exact official H24/METR-LA YAML `exp/forecast/ispikformer/ispikformer_metr-la.yml` sets window 12, horizon/out_size 24, `dim=256,d_ff=1024,depths=2,num_steps=4,heads=8,encoder_type=delta`; these are the adapter defaults apart from history/horizon following the local task. (The paper's Table 1 note says all SNN runs use convolutional encoders; this conflicts with that specific H24 YAML. The adapter follows the author repo's explicit H24 configuration and records the mismatch rather than claiming exact reproduction of Table 1.) Paper Table 1 evaluates H=6,24,48,96. Paper §3.2 gives delta encoding `SN(BN(Linear(Δx)))` Eq. (6) and convolution encoder `SN(BN(Conv(X)))` Eq. (7); §3.3 gives channel-wise spiking embedding and spiking attention; §3.4 predicts by a fully connected layer `Y=Linear(S_hidden)`; Appendix A.3 gives model setup.
- `SeqSNNForecast` imports the unchanged upstream `iSpikformer` and uses its source-defined direct multi-horizon `nn.Linear(dim, hmax)` wrapper, mirroring upstream `SNNVariateSpecTS` (`runner/snnvsts.py`) rather than modifying the SNN backbone. It treats each node-feature pair as a variate (`[B,L,N,F] -> [B,L,NF]`), takes only historical values, and reshapes the official shared per-variate H-step output to `[B,H,N,F]`. The final output is nonnegative count-scale via `softplus × train-fit output_scale`; this is the task's head adaptation. It uses no invented calendar fields. It does not use mask/age channels: the paper baseline assumes dense synchronous input, so masked bins are zero-filled; the intended email/MOOC count grids have complete observed bins. Verify input masks are all valid before main-table use; if not, report this unequal input allowance or freeze a mask-compatible ablation.
- Runtime dependency: local Conda already had Torch `2.11.0+cu128`; installed only `spikingjelly==0.0.0.0.14` using `pip --no-deps` after ordinary pip resolution proposed replacing Torch. No Torch replacement or legacy `snntorch`/full forecasting toolkit installation was performed. The official upstream package initializer imports unrelated stacks; the adapter isolates and loads the pinned unchanged iSpikformer source modules, with a minimal registry stub and unused `snntorch` namespace stub. Recheck this isolated import if changing source commits.
- CPU smoke: reduced `L=24,H=24,N=3,F=1`, dim 8/depth 1/steps 2/heads 2, finite output and finite parameter gradients passed. A separate no-grad CPU forward at `L=24,H=24,N=986,F=2` using the unchanged official-H24 width/depth (`dim=256,d_ff=1024,depths=2,steps=4,heads=8`) completed in 5.3 seconds and returned `[1,24,986,2]`; the shared head/backbone had 1,599,778 parameters and self-attention has 3,888,784 token-pair entries per spike step (`N*F` squared). This is a CPU smoke, not a batch/resource/training benchmark. Full test file passes 3 tests, including model creation through the engine's `build_model(...)` with its full `residual_scale` stats dictionary. Formal runs must still measure shared-load training memory/time and compare parameters/quality under the same tuning budget.

### SpikeSTAG and SpikySpace acquisition evidence

**SpikeSTAG author source was not found.** Search was for SpikeSTAG's title and GitHub code; the paper has no linked official repository in its inspected arXiv HTML. This is a search result, not proof that no source exists. The implemented `SpikeSTAGPaper` is explicitly exploratory and paper-derived, not an author reproduction and not sufficient evidence for the required faithful recent SNN main-table comparator. Use the SeqSNN official implementation above as the faithful recent forecast-method comparator; do not substitute the exploratory class for it.

The [full paper/HTML](https://arxiv.org/html/2508.02069) was read through the final references. Sections 4.1–4.5 specify adaptive graph `A=σ(EEᵀ)+λI` (Eq. 7), an OBS local-neighborhood attention (Eq. 8), thresholded and importance-ranked sampling (Eqs. 9–11), LIF dynamics (Eq. 1), SSA `SpikeSoftmax(QKᵀ/√dk)V` (Eq. 12), and LSTM/SSA gate fusion (Eq. 13). However, OBS attention's exact scoring details are deferred to Appendix A without a fully operational recipe in the HTML; SSA's spike-softmax, temporal spike encoding/decoding, LIF parameterization, and several sampling/batching choices remain unspecified. The paper uses minute/hour/day-of-week covariates (§3.1, §4.2), unavailable and invalid to invent for these relative-bin datasets. Its reported evaluation is 3 random seeds on Electricity/Solar (input 168, max horizon 48) and METR-LA/PEMS-BAY (input/horizon 12; §5.1/Table 1–2); it does not directly validate H=24 for event-count data.

Our exploratory class implements adaptive learned adjacency, threshold/top-k neighborhoods, two-scale aggregation with LIF units, an LSTM branch, spiking temporal attention, and a learned fusion gate. It makes unresolved paper choices explicit in code: fixed top-k cap, a simplified temporal encoding, dense adjacency construction before top-k, simplified OBS, and a conventional softmax-based attention current before LIF rather than a verified author SpikeSoftmax. Consequently the implementation may smoke-test but must not be labelled faithful or used as the sole required recent SNN baseline. No method score is reported.

SpikySpace is an additional acquisition candidate. The [paper record](https://arxiv.org/abs/2601.02411) points to [anonymous author archive](https://anonymous.4open.science/r/SpikySpace). The public project route returned a generic site shell; direct candidate archive URLs returned HTML rather than an archive, and `https://anonymous.4open.science/api/repo/SpikySpace` returned HTTP 401 in this inspection. No source files, commit, license, or runnable entry point could therefore be verified. Do not claim the project/code is absent; reacquire through an accessible author route and inspect state-space scan math, forecast head, dependencies, and license before any optional implementation.
