The focused local Conda run passed **3 tests, 21 deselected**; it covers the actual two-origin CPU frozen-model path, post-report P3A evidence mutation rejection, and postserialization stop-loss behavior. Source hash: `7c91a01f237d64c7f2db383fc31a823265edd7e42b4daa456744e755716302a7`.

- **H2 matched-retention v4 — acceptable as staging engineering.** The report writer runs the budget callback before serialization and after final integrity checks (`frozen_h2_matched_retention_v4.py:306-312,398-408`); the outer guarded wrapper checks again after `run_checkpoint_collection` and before writing the completed receipt (`:411-440`). The collection loop checks budget per origin (`:202-228`). Its suite passed **12 tests** under local Conda. I also ran a separate CPU toy mutation injection: changing canonical pipeline bytes immediately after the report artifact was written caused the final integrity check to reject the run while retaining the report. The successful two-origin test calls the real collection path with `PreparedData`, frozen checkpoint, model and kernel; resource/receipt wrapper behavior has separate mock coverage. Source hash: `6c4ff121436990b8aaf97993525ed9d995f2ded40e252022c78518a49643c578`.

- **Validation calibration v5 — needs a narrow final-stop-loss repair before execution.** Its main path calls the original `calibrate.calibrate_run` with a real CPU `ForecastModel`, real `PreparedData`, engine batches and at-launch binding verification (`frozen_validation_calibration_v5.py:559-585`; test `test_full_cpu_guarded_calibration_uses_real_original_calibrate_run`). A separate CPU toy injection mutated P3A-bound evidence after both calibration artifacts were written; final canonical validation rejected it and the receipt was not completed. However, the sole final `guard.checkpoint()` at line 632 occurs before the final input-hash snapshot, canonical-gate/evidence check, and checkpoint hash check at lines 633-637. Those hash/gate scans are part of the phase wall time. Add a final guard after the final fences (and the final receipt-input hash pass) before marking the phase completed.

## Shared scope limitation

All three drivers require P2/P3/P3A `passed/pass` and P4 `running`, and revalidate P3A hash-bound paths. They do not independently rehash P2/P3 bound inputs/evidence. Per root’s instruction, the managed P4 launch controller is expected to bind the canonical state and passed-phase archives before launch; this review does not treat driver-local stage status checks as equivalent.

Full per-driver source/test hashes, commands, and verdict metadata are in `frozen-driver-successors-independent-v2.json`. These checks establish only toy-path engineering behavior, not P3A/P4 acceptance or any scientific conclusion.
