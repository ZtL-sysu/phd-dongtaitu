# RP baseline compatibility screen (v2)

**Scope and status.** This is a bounded compatibility/source check for the P3A queue, not a performance comparison, literature-exhaustiveness claim, or novelty verdict. It uses the pinned local snapshots and earlier source/code audits, then checks primary project pages where needed. No training, validation, or test evaluation was run for this screen. “Pending” means the implementation/adaptation has not been verified; it does not mean incompatible.

## SNN family screening and fallback

- **SpikeNet**: [AAAI 2023 paper](https://ojs.aaai.org/index.php/AAAI/article/view/26034), [arXiv](https://arxiv.org/abs/2208.10364), [author code](https://github.com/EdisonLeeeee/SpikeNet). Its cited task is dynamic-graph node classification; the local literature map records a separate data download/DeepWalk feature pipeline. There is no forecasting head or common count-input/output smoke. Keep it as mechanism context/adaptation candidate; do not compare original classification metrics with MAE/RMSE.
- **Delay-DSGN**: [ICML 2025/PMLR paper](https://proceedings.mlr.press/v267/wang25dm.html) describes delay-based temporal propagation on evolving graphs for node classification. P1 search did not verify an author-code link; that is an unresolved search result, not proof no code exists. Forecasting head/input protocol and source route remain pending. It is not a numeric forecast comparator in its original form.
- **ChronoSpike**: [arXiv paper](https://arxiv.org/abs/2602.01124), [author-associated repository](https://github.com/Abrar2652/ChronoSpike). P1 records adaptive membrane/spatial-temporal graph representation learning for node classification; local author-tree/entrypoint/license audit and a forecasting adaptation are not established. Keep as related method/adaptation candidate, not current forecasting queue.
- **SpikeSTAG**: [full paper](https://arxiv.org/html/2508.02069). It is the closest listed combined graph+SNN multistep forecasting threat. P2 inspected the full HTML but found no author repository link there and identified underspecified OBS/SpikeSoftmax/encoding/LIF choices plus unavailable relative-time calendar covariates. The local `SpikeSTAGPaper` is explicitly exploratory and not faithful. It must not stand in the main table as a faithful reproduction.
- **SpikySpace**: [paper](https://arxiv.org/abs/2601.02411), [anonymous author archive](https://anonymous.4open.science/r/SpikySpace). Forecasting SNN/state-space method, directly relevant to the planned temporal selective computation. Prior inspection received a generic shell / HTTP 401 from the API and verified no source file, commit, license or executable; this does not establish source absence. Acquisition/source-faithfulness remains unresolved.

**Fallback decision:** official SeqSNN is a real, locally smoke-tested forecasting SNN and is the correct executable SNN comparator now; it is not a methodological substitute for SpikeSTAG or SpikySpace. Before P3A closes for any broader claim, record a bounded acquisition/faithfulness decision for both forecasting papers (source reachable and tested; or a paper-derived implementation with equations and assumptions audited; or an explicit scope limitation accepted by the project owner). Keep SpikeSTAG exploratory code out of the faithful main table. The classification-only methods need a declared forecasting adaptation before numerical inclusion; task mismatch, rather than poor performance, is the reason their original results are excluded.

## Recommended exact P3A queue and gate

1. **Current campaign queue** remains the already frozen development seed-0 methods `GRU, V0, V1, DGCRN, SeqSNN, STID` on the selected synthetic, email, MOOC, and email-episode datasets, with resource sizes from `protocols/p3-training-resource-contract-v2.json`. Run only the queue authorized by the owner and cumulative budget guard; this screen authorizes no training. These resource settings do not imply the other compatible RP baselines are unnecessary.
2. Add/resolve the RP forecasting family as pending entries in this order: **Graph WaveNet, AGCRN, STAEformer, DCRNN**. The first three have a plausible isolated PyTorch route but no adapter/smoke yet; DCRNN has a known TF ≥1.3 official stack and an explicitly required training-period graph prior, so it needs a source-faithfulness/dependency-route decision before launching. Do not turn resource pressure or expected score into an incompatibility claim. If the fixed P3 resource/budget protocol cannot accommodate one, surface that as an explicit coverage gap and obtain a scope decision; pending is not pass.
3. Maintain two separate nonnumeric acquisition gates: **SpikeSTAG** (complete-method-detail/source-faithfulness gap) and **SpikySpace** (archive/source/license/access gap). SeqSNN satisfies the requirement for an executable recent SNN forecasting comparator, but leaves these high-similarity method checks open. Do not run `SpikeNet`, `Delay-DSGN`, or `ChronoSpike` as forecast baselines without a forecast-specific adapter and causal input/head protocol.
4. Before any final-test use or broad baseline-coverage claim, P3A should have immutable source/config/data bindings, exact L/H/F and raw-unit count-head evidence, only train/validation model selection, no future covariates/labels, valid full-window handling for methods that ignore masks, parameter counts and resource records, and an explicit disposition for every pending item above. All methods must use the same target partitions and comparable tuning allowance; any deviation is reported, not hidden behind original paper scores.

## Evidence limitations

No numeric performance ordering, baseline inadequacy, or method superiority is inferred here. Local smoke/test records are correctness evidence only. Pinned source hashes identify inspected snapshots, not proof of upstream reproducibility. The STAEformer license status, remaining adapters/smokes, final resource feasibility of pending models, and accessible faithful SpikeSTAG/SpikySpace source are unresolved. The P3A/P3 scientific gates remain separate and are not passed by this report.
