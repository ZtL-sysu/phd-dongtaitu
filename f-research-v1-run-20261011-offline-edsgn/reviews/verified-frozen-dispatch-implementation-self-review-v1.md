# Verified frozen dispatcher v1 — implementation self-review

**Role and scope.** This is a writer self-review of a staging dispatcher, not an independent review or scientific acceptance. It does not modify `edsgn/src`, pipeline state, active resource queues, or child drivers. No real child, model, data arrays, checkpoint, GPU, training, or calibration was run.

The dispatcher accepts only an in-run JSON job (`--job` is the sole CLI argument), four enumerated driver identities, and each driver's fixed required/optional flags. It builds argv tokens and invokes a fixed Conda Python with `shell=False`; unknown flags, duplicate flags/JSON keys, missing required flags, outside-root paths, symlinks in frozen trees, missing input paths, existing output paths, and output paths with absent parents fail closed. Directory source digests are the SHA256 of canonical sorted relative-path/file-SHA256 mappings; every regular descendant file is captured, symlinks are rejected, and empty directories are outside the declared membership definition.

Before child execution it snapshots canonical `pipeline-state.json`, the contract artifacts, all passed-stage inputs/evidence, the copied validator bundle, dispatcher, driver, job, all declared source trees/files, and all input path arguments. It requires P4 to be running and invokes the copied official `pipeline_state.py --before P4`. After a zero child exit it compares the complete file map and pipeline bytes, reruns the validator, rechecks the pinned validator hashes, and takes a final byte snapshot. Only that path records `accepted-output-pending-scientific-review`; dispatcher failures never advance pipeline state. The dispatcher acquires no resource locks. It emits no extra `offline-phase-wall` entry; the child owns its original receipt, avoiding parent/child double counting.

The f-research validator copy is bound by [verified-pipeline-validator-source-v1.json](../protocols/verified-pipeline-validator-source-v1.json). The dispatcher itself is intentionally absent from the owned model-process scanner's name list. CPU mock tests cover success with both validator invocations, stale P2 evidence before launch, P3 evidence mutation after child, recursive source membership drift, failed stage verdict, out-of-root and unapproved argv, and scanner classification.

Validation: `dyg-cold` pytest, **6 passed**; see [verified-frozen-dispatch-v1-tests.log](../logs/verified-frozen-dispatch-v1-tests.log). Dispatcher SHA256: `4c2ff438a5d221c43764ba61420916625d9d903343992ac889cea17b8e3f6e61`.

**Limits for root acceptance.** No actual job JSON was authorized or created, no allowlisted child was launched, and no claim is made that any output is valid. Review root/P4 integration and accept the dispatcher before preparing a real immutable job. A process killed externally before Python finalization may leave no completed receipt; ordinary Python exceptions and nonzero child exits are recorded. Existing per-child locking, budget, owned-process scan, and scientific review remain delegated to each frozen child and the root pipeline.
