# Serial guarded resource-probe queue driver v1

Added inert, outside-package queue driver `edsgn/staging/serial_resource_queue_v1.py` and fake-process tests `edsgn/staging/test_serial_resource_queue_v1.py`.

The driver validates the queue's exact Conda interpreter, `baseline_resource_probe.py`, config/output paths, batch size, `--repeats 1`, and train-only one-forward/backward/no-optimizer row before any launch. Config digests are read from the queue's frozen `configs[]` entries; queue item rows do not contain their own digest. It requires queue status `accepted` or `accepted_for_resource_probe` and `pipeline-state.json` P2=passed/P3=running. It takes exclusive `logs/offline-phase-wall/campaign.lock` and `logs/model-resource.lock`, calls the existing owned-process detector before each child, uses at most one child at a time, and terminates only its own child at the 600-second per-attempt cap or the cumulative stop-loss.

Per-attempt resource/functionality receipts update whole-attempt `wall_seconds` while a child runs. Before/after source fences use `bind_training_inputs._code_paths`, `_dataset_source_files`, the exact config, prior artifacts, probe/guard scripts, and adapter upstream Python/license/readme files; these operations hash files without loading dataset arrays. After a started child finishes, an exclusive versioned manual-ledger snapshot is written, then an atomic measured entry covers both parent receipt and child report with `max(parent wall, child wall)` to prevent double counting. A later run reuses only a completed report with matching current source/config/data/upstream hashes; failed, partial, unbound, or changed outputs stop the queue and remain untouched.

Mock-only local Conda tests: **5 passed**. They simulate a successful child and verify aggregate ledger deduplication, failed-child halt/preservation, timeout termination of only the owned child, cumulative-budget refusal/recheck, and a foreign lock. No real model/data arrays were loaded; no GPU child was spawned and no queue/config/accepted output was changed.

The live `resource-probe-queue.json` remains `proposed_unlaunched_unaccepted`; the driver correctly refuses to launch until root accepts it and P2/P3 are in the required state. The first config's live SHA-256 (`synthetic-GraphWaveNet-seed0.json`) is `9089e2e2e9138cfd478e20493f313f937c156708f50392b10a69b52472c30d1e`, matching `configs[0].config_sha256`. This task did not execute a real queue preflight while the separate GPU probe was active.
