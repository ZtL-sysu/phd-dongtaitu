# Frozen profile v5 independent review

**Verdict: acceptable for gated engineering preparation, with the accounting/status limits below.** This is a source and CPU-toy review only; it is not a real profile run, test evaluation, or scientific result.

Reviewed `edsgn/staging/frozen_profile_guarded_v5.py`, its 11 CPU toy tests, and the underlying `edsgn/src/edsgn/profile.py` measurement path. Under the local `dyg-cold` Conda environment, `pytest edsgn/tests/test_frozen_profile_guarded_v5.py -q` passed: **11 passed in 14.44s**. Tests construct temporary NPZ bundles and a tiny CPU model; they do not touch run datasets/checkpoints or use a GPU.

The profile wrapper binds the checkpoint's training-data path before collection loading, snapshots that complete training collection and all source/package bytes, and requires training `PreparedData` mean/std/residual scale to exactly equal checkpoint statistics. Synthetic validation/test views are recomputed with the frozen training normalizer; non-synthetic views must already match it. The tests verify the resulting inputs use train statistics and detect main-training-collection mutation.

For single-bundle sources, the initial receipt conservatively records possible/attempted numeric materialization before loading. On successful load it distinguishes materialized test values/suffix from origin evaluation. Test execution is marked started before calling the actual profiler; completion flags become true only after the full call returns. Tests cover failure before evaluation and successful completion. A failure after some windows have run would retain `test_evaluation_started=true` but has no incremental completed-origin counter; `test_origins_evaluated=false` therefore should be interpreted only alongside `test_origin_evaluation_complete=false`, not as proof that zero origins ran.

The underlying `profile_run` performs full, ordered B1 FP32 replay with ten warmup windows and five repeats, and synchronizes around measured forward calls. The wrapper checks the CSV has exactly five copies of the canonical origin order. Guard checks occur before each prepared window; their host overhead is separately recorded and removed from preprocessing estimates, leaving model-forward measurements untouched. Trace diagnostics select at most eight evenly spaced windows, trace disk-write time is separate, and CUDA host component diagnostics are explicitly not treated as device elapsed time. Blind `periodic`/`random` control execution applies the accepted helper to the live policy, validates the frozen extra and root acceptance record, includes helper/acceptance bytes in the snapshot, and revalidates after output serialization.

Both `logs/model-resource.lock` and `logs/offline-phase-wall/campaign.lock` are created exclusively and released in `finally`; the tests verify cleanup on success and failures. The wrapper rechecks all source/data/freeze/policy bytes, canonical state, official predecessor gate, blind-helper binding, output hashes, and cumulative budget before writing the completed receipt.

Two bounded limitations remain. The final cumulative budget check and all file/gate checks precede the final completed-receipt serialization, so that last small write is outside the stop-loss recheck. Also, the test receipt has start and full-completion flags but no incremental per-origin progress on a mid-replay exception. Neither limitation affects the successful toy replay, but both should remain explicit when interpreting a failed real receipt and its wall accounting.

No actual checkpoint, dataset, test/oracle array, GPU, optimizer, or phase launch was used.
