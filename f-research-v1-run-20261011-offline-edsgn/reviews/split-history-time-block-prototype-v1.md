# Split-history time-block robustness prototype

The metadata-only preflight found that the prior time-block RNG sampled starts over the full trajectory. Consequently the email, MOOC, and email-episode blocks missed every complete held-out origin history at rates 0.1/0.3/0.5. The new staging-only prototype in `edsgn/staging/split_history_robustness_v1.py` changes only that placement universe.

For the declared split it obtains complete origins from `PreparedData.origins(split)`, then computes the exact half-open union `[first_origin-history+1, last_origin+1)`. It sets `block_length=round(union_length*rate)` (minimum one for a positive rate) and samples a legal contiguous start uniformly inside that union with the existing `_stable_seed(recipe_seed, trajectory_index, source_seed)` and RNG substream. Recipe seed is fixed to 2027. Rate zero creates no block and consumes no placement draw. There is no seed/window/result selection.

Only time-block uses the new placement. The constructor delegates count-noise and explicit event jitter construction to `RobustnessPreparedData` with time-block rate zero, then masks the already prepared causal input arrays over the new block and recomputes age from the effective visibility mask. `target()` remains inherited and delegates directly to the clean data. Random and related-group recipes route unchanged to the original wrapper. Given the same split, recipe seed, source seed, trajectory index, and clean input mask, each method receives the identical visibility mask.

Freeze helpers bind the wrapper source SHA, domain-manifest path and SHA, canonical recipe digest, selected split, per-trajectory source seed/index, complete-origin range, history-union interval, and exact block interval. The bundle form stores every trajectory placement. Validation recomputes this metadata and rejects absent metadata, byte/hash changes, changed split/recipe/range, or a truncated trajectory list. The caller must include the returned `split_history_time_block` or `split_history_time_block_bundle` field in the immutable test-freeze extras; this prototype does not alter package freeze logic or the replay driver.

Six CPU toy tests passed. They verify positive held-out-history coverage for a positive rate, legal interval/rate arithmetic, deterministic placement, shared masks across repeated method-independent constructions, unchanged target values/masks, recomputed source age, unchanged count-noise/event-jitter behavior, unchanged random/group wrapper routing, and rejection of empty ranges and missing/tampered freeze metadata. Tests use in-memory `PreparedData` and temporary toy manifests only. No prepared dataset, test target, model, GPU, optimizer, or replay was accessed. See `logs/split-history-robustness-toy-v1.log` and `.json`.

Scope: prospective P3/R2 engineering preparation. The code is not integrated into `edsgn/robustness.py` or a test replay CLI and provides no robustness result. Integration must keep each declared split fixed before outcomes and preserve the same mask across methods.
