# Frozen graph/state diagnostic preparation v2

This is a staging-only successor to v1. The v1 script, tests, review, and logs remain unchanged. The diagnostic is not integrated into the package or evaluation controller and was not run against a real test collection.

The v2 artifact format keeps predictions, raw targets, target masks, origin/seed IDs, required-horizon metrics, per-origin counters, and compact per-step rows for every frozen test origin. Compact rows retain affected graph/state row IDs, aligned graph-change signal `c`, support-aligned row TV, consumed `log_g`/`g`, graph/state ages, effective ages, and input observation age. A compact row stores no full membrane/spike arrays or full supports. Full support IDs/weights and `u`/spike/reset snapshots are emitted only for a deterministic, frozen selection of at most eight uniformly spaced origins per trajectory and node IDs `0..min(7,N-1)`. Structural oracle alignment is explicitly sample-only; full-origin prediction/TV/c/g/counter coverage is retained.

`frozen_diagnostic_extras(dataset_paths, trace_selections, max_artifact_gib=8)` binds the selector version, exact per-trajectory sampled origins and node IDs, the artifact cap, diagnostic/model trace source hashes, complete test+oracle collection fingerprints, and hashes for the aggregate-budget and process-scan helper sources. The CLI checks checkpoint bytes and those source/selector bindings before importing resource helpers or acquiring resource leases. Replay recomputes and compares the frozen sample, verifies the exact full origin list, rechecks model/checkpoint/freeze/helper hashes at the end, and fingerprints all test and oracle bytes again after oracle reads and all analyses.

Before creating output, the runner computes a conservative uncompressed artifact bound (compact rows scaled by node count, sampled detail scaled by `d_total`, prediction arrays, and fixed overhead), applies an immutable explicit cap, and requires free space at least 1.25 times the estimate. It records the estimate/free-space values and `serialization_seconds` separately (the final report's own serialization is explicitly excluded). The report labels component timing as `diagnostic_overhead_not_profile_or_energy`; no profiling or energy claim is made. `predictions.npz` now includes `seed_id` for downstream seed-aware aggregation.

CPU verification used the local `dyg-cold` Conda interpreter with `PYTHONPATH` explicitly set to `<run>\edsgn\src;<run>\edsgn\scripts;<run>\edsgn\staging` and OMP/MKL thread counts set to 2. `py_compile` passed and the v2 test file passed **10/10**. The toy checks cover deterministic selection, strict support-ID validity for TV, compact versus detailed trace shape, age/c/g/TV fields, seed mapping, artifact/disk rejection, changed collection fingerprint, changed resource-helper hash, and freeze selection binding. The model parity toy confirms passive capture does not change predictions, graph loss, or final membrane state.

No real prepared/test arrays, oracle NPZs, checkpoint, GPU, optimizer, or replay were accessed. The prototype still requires root integration into the immutable freeze and a separate gate-approved replay; this evidence is engineering preparation only and does not imply P3A/P4/P5 completion or a scientific result.
